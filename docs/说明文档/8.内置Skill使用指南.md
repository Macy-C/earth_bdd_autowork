# 8. 内置 Skill 使用指南
文档哈希（SHA256）：`e0da6d2744b28ae5af290fa5eabf93b4e8129703730bc32e4ecfc6d92df55ee7`

本文面向在 VS Code / GitHub Copilot 中使用 BDD Autowork 的脚本编写者和维护者，说明
仓库内置 Skill 的用途、调用方式、输入、结果及注意事项。

Skill 是可选的 AI 任务入口，不是框架运行依赖。已有的 Runner、调试工具、运行知识采集、
Markdown 导出、报告处理和知识库客户端仍可独立使用。不使用 AI 时，按
[快速开始](1.快速开始.md)和[运行知识采集](7.运行知识采集.md)中的原有入口操作即可。

## 内置 Skill 总览

当前仓库包含以下 4 个面向普通用户请求的内置 Skill。

| Skill | 适用任务 | 主要输入 | 结果与边界 |
| --- | --- | --- | --- |
| [`bdd-knowledge-generate`](../../.github/skills/bdd-knowledge-generate/SKILL.md) | 参考已有案例和 Wiki，为已有 Feature 补齐或新增 Step、Page/View、data 实现 | Feature 路径、Scenario/Outline/Example 范围及适用规格 | 代码或明确的候选/阻塞说明；不隐含执行产品测试 |
| [`knowledge-assist`](../../.github/skills/knowledge-assist/SKILL.md) | 导出、分析、校验、润色和发布运行案例，查询处理状态，审阅 Wiki | 已有案例文件或采集选择；远端动作另需目标库 | 按请求分别处理，不强制串联润色、上传和验收 |
| [`document-sync`](../../.github/skills/document-sync/SKILL.md) | 刷新文档哈希、比较知识库版本、上传 Markdown、确认更新及查询任务 | 本地 Markdown、目标知识库或已有任务 ID | 检查不写远端；普通上传不删除；更新需确认 |
| [`report-merge`](../../.github/skills/report-merge/SKILL.md) | 创建最终报告、回填运行结果、删除指定结果、重建 HTML、预览及分析 | 源报告、目标最终报告及操作范围 | 复用原报告能力，不替用户运行测试 |

协作复盘和规则晋升位于 [Prompt 入口目录](../../.github/COPILOT.md)，不是上述 Skill。
编辑器或扩展另外提供的 Python 等 Skill 也不属于本框架内置清单。

## 如何调用

### 使用前准备

1. 在支持仓库 Skill 的 Copilot 环境中打开项目根目录，保留随框架交付的
   [.github](../../.github/COPILOT.md) 和 [ai](../../ai/README.md) 目录。
2. 使用已有可用的项目解释器。仅查文档不要求安装 Python；需要运行框架命令时才使用
   该解释器。缺失依赖应先报告，不把普通任务自动扩展为安装或环境修复。
3. 需要知识检索时，准备可访问目标库的只读 WeKnora MCP 工具；程序上传和相关远端
   管理还需要项目已有的 REST 配置与权限。MCP Token 不能替代 REST API Key。
4. 提供明确的文件或场景范围。不要把密码、API Key、患者数据等敏感内容粘贴进请求。

本地校验、纯润色、报告处理不要求 WeKnora。已有运行的自动采集和基础导出也不要求 AI。

### 自然语言与显式选择

可以直接描述目标，让宿主按请求选择相关 Skill；为了明确路由，也可以在支持该功能的
Skill 选择器中显式选择，或通过 `/<Skill 名称>` 的补全入口选择后填写请求。例如：

```text
/document-sync 检查第 1-7 份指南与“框架知识库”是否一致，只检查，不上传。
```

斜杠入口、自动发现和工具可用性取决于当前宿主及其配置。自然语言相关性不保证宿主每次
都会加载 Skill；若没有显示对应入口，应先确认工作区和宿主支持，不反复执行业务命令来试。

以下示例均为请求模板：替换文件路径、场景名称、知识库和任务 ID；不要原样执行占位符。
通常只需说明目标，不需要用户手工创建内部规格 JSON、审阅 JSON 或拼装 HTTP 请求。

## 知识增强 BDD 生成

### 什么时候用

使用 `bdd-knowledge-generate` 为已有 Feature 中指定的 Scenario、Outline 或 Example
补齐实现。它结合当前项目代码、已有定位器、认可的工程案例和适用产品资料进行生成。
知识库来源绑定以 `Bdd/config.yaml`（`WEKNORA_SETTING.KNOWLEDGE_BASES`）为准，不把所有可访问知识库自动当成
认可来源，也不把历史截图当作当前 UI 的证明。

```text
使用 bdd-knowledge-generate，为 Bdd/test_features/my_product/demo.feature 中的
“查询记录”场景补齐实现。复用现有 Page/View 和定位器；本轮只生成及静态校验，不运行产品。
```

```text
只分析 demo.feature 中“查询记录”的实现方案、可复用能力和缺失证据，不修改文件。
```

### 会得到什么

默认采用无人值守方式处理可据证据决定的事项；必要问题和限制会写入交付结果，不能据此
理解为可以猜测业务规则。当前生成工作流区分三类结果：

| 证据情况 | 交付 |
| --- | --- |
| 证据充分，可完整支持实现 | Step `.py`；不额外创建不必要的伴随文档 |
| 可形成有依据的完整候选，但存在待确认项或非致命限制 | Step `.py` 加同目录同名 `.md`，状态为 `needs_confirmation` |
| 缺定位器、契约或关键流程，必须虚构实现才能继续 | 只写同名 `.md`，状态为 `blocked`，不写占位代码冒充完成 |

有伴随文档时，阅读问题和限制，填写实际答案或勾选选项后再请求继续。例如：

```text
已填写目标 Step 同名 .md 中的答案，请据此继续实现并重新静态校验；仍不运行产品。
```

### 注意事项

- Feature 默认是只读业务输入，不改场景来迎合现有代码。已有 locator 文件也保持只读；
  有证据支持的新定位写在允许的 Step 局部范围，不借生成重构共享资产。
- 生成和静态通过不等于已实跑，更不等于业务预期已验证；实跑需要另行明确范围与条件。
- 只要求方案或解释时不落盘。调试、维护、运行案例发布不是此 Skill 的替代用途。

脚本结构见 [编写自动化脚本](2.编写自动化脚本.md)，详细工作流见
[生成正文](../../ai/prompts/bdd-knowledge-generate.md)。入口存在不等于当前宿主已通过自动发现、
工具连通和目标产品生成效果验收。

## 运行案例辅助

使用 `knowledge-assist` 处理运行采集形成的案例。先说明要分析、校验、润色还是上传；
普通 Markdown 文档同步则使用下一节的 `document-sync`，不混用两者的内容契约。

```text
使用 knowledge-assist，只分析指定采集目录中的“查询记录”运行证据，指出未验证事项，
不修改文件、不上传。
```

```text
使用 knowledge-assist，校验 artifacts/knowledge-captures/<run-id>/<case>.md。
然后只润色叙事，生成新副本，保留原件，不上传。
```

```text
使用 knowledge-assist，将指定案例 Markdown 原样上传到“项目工程案例库”，不要再次润色。
```

```text
查询该案例的解析进度；只看处理状态，不做 Wiki 验收。
```

```text
审阅该案例对应的当前 Wiki 内容，核对动作顺序、控件归属、图片引用和推论边界；
尚不能确认的项目如实说明，不删除旧版或本地采集。
```

需要分清的状态：

| 状态或动作 | 表示什么 | 不表示什么 |
| --- | --- | --- |
| 基础导出、结构校验 | 本地产物生成或结构满足检查 | 场景业务正确、运行证据完整 |
| 润色 | 受保护叙事的新副本通过校验 | 原件被覆盖、内容已经上传 |
| 文件上传、远端回读 | 上传结果及字节核验状态 | 解析、摘要、标签、Wiki 全部成功 |
| 处理状态查询 | 解析或摘要当前进度 | 完整文件核验或 Wiki 接受 |
| Wiki 接受 | 当前文档与 Wiki 版本绑定的审阅已记录 | 自动删除旧版或清理本地采集 |

注意：

- 运行结束的基础 Markdown 自动导出不依赖此 Skill，失败或不完整现场也会如实导出。
  主动 `build` 的候选选择要求完整通过，不能替代失败现场的自动记录。
- 显式文件就是输入边界，不扫描别的采集来替换它。再次润色产生新副本，不覆盖原件。
- 新发布使用知识库根目录和小写 `feature:<Feature 文件名 stem>` 标签；已有回执保持
  原绑定。标签、字节核验、解析和 Wiki 状态分开报告。
- 上传结果未知或验证待完成时，先查询原提交；不要换名、重建文件或重复上传绕过它。
- 退役旧版和清理本地采集必须独立明确请求；清理只针对已结束且满足当前接受与退役条件
  的完整 Run。不要为了整理目录手删原始观察或 PNG。

详细说明见 [运行知识采集](7.运行知识采集.md)及
[案例辅助正文](../../ai/prompts/knowledge-assist.md)。

## 框架文档同步

使用 `document-sync` 处理本地 `docs/` 目录层级与明确知识库的版本检查、目录同步、普通上传和确认更新。

```text
使用 document-sync，检查 docs/ 目录与“框架知识库”是否需要同步。
```

```text
只检查 docs/说明文档/8.内置Skill使用指南.md 与“框架知识库”是否一致，不上传、不继续更新。
```

```text
使用 document-sync，上传 docs/说明文档/8.内置Skill使用指南.md 到“框架知识库”，不替换或删除已有文档。
```

```text
查询更新任务 <task-id> 的阶段、异常和旧版是否保留，不恢复任务。
```

注意：

- 未指定文件时，目录检查/刷新默认递归选择 `docs/` 下全部 Markdown 文档（保留 `说明文档` 与 `维护文档` 相对目录）；也可明确给出单份文档或子目录路径。
- 刷新、检查、上传、更新会先刷新本地头部哈希；检查可能改这一行，但不改正文、不写远端。
- 普通检查发现已核实差异后会询问后续选择；明确“只检查”则报告结果后结束。
- 普通上传不会删除旧版。同名冲突、缺失、读取失败和未结束任务分别报告，不混为更新许可。
- 确认更新表示创建新版、以状态标签标记并保留旧版，新版验证成功后才删除指定旧 ID。
  新 ID 会改变，旧引用不会自动迁移，并存期间可能检索到两版。
- 上传已接收、任务已启动不等于更新完成。后台可继续处理，但本机休眠、断网或退出会影响
  执行；暂停后应查询原任务，明确恢复或取消，不重复上传来代替恢复。
- 取消不删除已上传新版，也不能撤销已提交的删除。旧任务确认内容与当前文件不同时，不能
  直接拿旧授权提交新内容。不要手改任务文件或把暂停记录改成成功。

任务 ID 和当前阶段应由执行结果返回，用户无需寻找内部 JSON。详细规则见
[文档同步正文](../../ai/prompts/document-sync.md)。

## 最终报告处理

使用 `report-merge` 处理现有报告，不启动测试。常见顺序是：先创建一次最终报告，后续运行
产生新报告后，再将新结果回填到这个最终报告中。

```text
使用 report-merge，以 artifacts/reports/autowork-report.json 创建最终报告，
另存到 artifacts/final-reports/delivery.json，不覆盖已有文件。
```

```text
把本次运行报告合并到已有最终报告，保留本次没有执行的场景和 Example；先预览，不写文件。
```

```text
从指定最终报告中删除 Feature“计算器”的 Scenario“计算相加”结果，其他结果和原始附件保留。
```

```text
只重新生成指定最终报告的 HTML，不改测试结果，不合并，也不重新运行测试。
```

注意：

- 源/目标路径明确时优先使用指定路径；未指定时沿用项目已有默认，不按文件修改时间猜报告。
- 创建、合并、删除结果、渲染、分析是不同动作。目标不存在时，不能把“合并”自动变成“创建”。
- 普通合并保留目标中未提及的结果；追加新对象、整组替换 Feature/Outline 需要明确要求。
- 删除的是报告内指定结果，不是报告文件、截图或录屏；删除最后一个子项可能连带移除空组。
- 预览和分析不落盘；正式写入按真实状态记录 passed/failed，不借 AI 分析美化结果。
- HTML 重建不能修复已缺失的附件。发生部分写入时应查看实际输出，不假定已自动回滚。

范围与冲突处理见 [报告工作流](../../ai/prompts/report-merge.md)。

## 常见问题与使用习惯

| 问题 | 建议 |
| --- | --- |
| 自动选择了不合适的 Skill | 显式选择正确入口，并说明“只分析”“只上传”“不运行”等边界 |
| 工具或知识库不可用 | 报告缺失能力及影响；需要远端事实的部分不能当作已核实，不自动换协议或修环境 |
| 请求已明确仍反复被问路径或范围 | 在当前任务中沿用已确认信息；真正同名冲突、内容变化或新写入范围再确认 |
| 后台更新一直没有完成 | 用原任务 ID 查询阶段和异常；不要重复上传，也不要把卡片解析完成当作删旧完成 |
| 文件上传成功，但标签、摘要或 Wiki 未成功 | 分别查看返回状态，不混成一次全部成功，也不凭失败子状态重传已上传文件 |
| 想让 AI 诊断失败报告 | 明确只读分析；复跑、改测试代码或合并报告分别授权，不靠改断言制造通过 |

建议一次请求说明“目标对象＋动作＋范围＋禁止顺带做的事”。例如：

```text
使用 knowledge-assist，只校验指定案例并报告问题；不改原件、不润色、不上传。
```

执行结束应查看实际输出文件、范围、状态和未完成事项。耗时、检查通过、代码生成、
上传接收、业务结果验证是不同证据，不能相互替代。本指南不承诺固定响应时间或生成成功率。

各 Skill 的权威规则以当前入口和其链接的工作流正文为准；新增或修改 Skill 时，应同步
更新本文总览及相关示例，但不把本指南当成新的运行协议。
