# 6. 版本与升级说明
文档哈希（SHA256）：`6a93e6d494e50fdf81c39628c4c108d34054b22414a18cfca76455a146ae00ff`

本文记录BDD Autowork框架发布版本及升级影响。内部Evidence、Plan、Transaction、
Run Result等协议各自独立演进，其协议版本不等于框架发布版本。

## 当前版本

| 项目 | 值 |
| --- | --- |
| 最新记录的发布版本 | `1.1.0` |
| 发布日期 | 2026-08-25 |
| 状态 | 向后兼容功能更新 |

框架发布版本使用`MAJOR.MINOR.PATCH`：不兼容的公开契约变化升级`MAJOR`，向后兼容的
功能升级`MINOR`，向后兼容的缺陷修复升级`PATCH`。正式发布提交应创建同版本
`vMAJOR.MINOR.PATCH` Git标签；协议版本继续由各自代码和设计文档管理。

本文滚动保留最新三个版本条目。由于`1.0.0`之前没有正式Git标签，历史开发里程碑明确
记为开发里程碑，不追溯伪造发布版本，也不能作为受支持的降级目标。

版本条目记录发布历史；下述使用示例按当前源码维护。开发中的代码、工作区未提交修改
和内部协议不能只凭发布版本号判定一致，排障时还应核对实际提交与相关文件内容。

## 升级前的范围确认

输入是明确的框架发布源和目标宿主项目。先核对当前提交与本地修改，再按对应版本
条目更新；版本号相同不能证明未提交代码、依赖或内部协议一致。

| 资产或检查 | 正确处理 | 完成后能证明什么 |
| --- | --- | --- |
| 框架目录及根配置代码 | 按明确发布源更新，核对实际差异 | 框架文件已对齐，不证明宿主业务通过 |
| `Bdd/`、项目配置、项目知识 | 保留宿主实现，不用框架目录整体覆盖 | 宿主资产未被同步覆盖 |
| `artifacts/` | 按证据与保留要求独立管理 | 不因升级自动删除运行或录制记录 |
| `framework_smoke` | 在宿主根目录执行轻量检查 | 同步、配置及关键导入健康，不代表产品验收 |
| 宿主测试 | 宿主 `Bdd/` 也发生变化时运行对应检查 | 仅覆盖实际执行的宿主行为 |

## 当前最终报告的使用方法

适用于已有普通 Spark JSON，需汇总初次运行与复跑结果的情况。输入报告必须来自明确
的 Feature/Scenario/Example；创建或合并报告不会重新执行测试，也不会把缺少证据的
场景补成通过。

### 选择操作、输入和输出

宿主入口为 `Bdd/final_report.py`：顶部只配置默认输入/输出路径，在对应方法中填写
操作参数，文件底部选择一个调用。没有顶部 `ACTION` 配置块；需要 CLI 时使用核心模块
或宿主入口的实际命令行参数。

| 操作 | 输入与前提 | 输出与边界 |
| --- | --- | --- |
| `create` | 已有普通 Spark JSON；明确目标最终报告路径 | 创建底稿并渲染 HTML，不读取未来的复跑结果 |
| `merge` | 已有最终报告和本次普通报告；必要时指定 Feature/Scenario/Example | 合并指定结果并刷新 HTML；示例显式 `allow_add=False`，不将未匹配的新项作为默认选择 |
| `delete` | 已有最终报告和明确的结果选择条件 | 从最终报告删除误合并结果并刷新 HTML，不删除被测产品数据 |
| `render` | 已有有效最终 JSON | 重新生成 HTML，不运行测试或重判断言 |

核心函数的调用形状如下。路径和选择条件是示例，使用前替换为真实报告与实际场景；
以下定义本身不会执行操作。

```python
from autowork_core.runtime.reporting.final_report import create, delete, merge, render

DEFAULT_INPUT_REPORT_JSON = "artifacts/reports/autowork-report.json"
DEFAULT_FINAL_REPORT_JSON = "artifacts/final-reports/autowork-final-report.json"


def create_final_report():
  return create(
    DEFAULT_INPUT_REPORT_JSON,
    final_report_json=DEFAULT_FINAL_REPORT_JSON,
  )


def merge_final_report():
  return merge(
    DEFAULT_INPUT_REPORT_JSON,
    final_report_json=DEFAULT_FINAL_REPORT_JSON,
    allow_add=False,
    # 需要限定复跑范围时填写真实选择条件：
    # feature_file="Bdd/test_features/login.feature",
    # scenario_name="登录成功",
    # example_id="1.1",
  )


def delete_from_final_report():
  return delete(
    final_report_json=DEFAULT_FINAL_REPORT_JSON,
    feature_file="Bdd/test_features/login.feature",
    scenario_name="误合并的场景",
  )


def render_final_report():
  return render(final_report_json=DEFAULT_FINAL_REPORT_JSON)
```

`create`、`merge`、`delete` 都会刷新最终 HTML，不必再额外调用 `render`。`target_report`
仍是核心函数支持的兼容参数，当前示例统一使用 `final_report_json`；核心函数参数
不能与宿主方法名或 CLI 选项名混用。

### 执行后核对交付结果

方法返回最终 JSON 与 HTML 路径。默认输出如下；改变路径时以实际返回值和配置为准：

| 产物 | 用途 | 不能代替什么 |
| --- | --- | --- |
| `artifacts/final-reports/autowork-final-report.json` | 最终报告结构化正文 | 不可变的原始执行记录 |
| `artifacts/final-reports/autowork-final-report.html` | 对外交付和人工查看 | 未执行场景的业务验证 |
| `artifacts/final-reports/autowork-final-merge.json` | 内部操作日志 | 交付报告正文 |
| `artifacts/final-reports/assets/` | 合并时保存的截图、录屏及附件快照 | 原 Run 的完整审计归档 |

复核目标场景、Example、状态和附件是否符合本次选择。普通报告仅表示最近一次执行，
不能将合并后的展示状态理解为每次尝试都成功；输入报告或选择条件有误时先核对来源，
不要靠删失败结果改变验收结论。

## 1.1.0 - 2026-08-25

向后兼容功能更新，重点改善大量场景报告查看和最终交付报告合并流程。
本条记录发布内容；当前调用方式见上节，不将当前示例代码反推为全部历史提交的接口。

### 1.1.0 主要变化

- Spark测试详情页优化大量Scenario/Example浏览：压缩左侧导航行，保留列表滚动位置，
  切换场景时右侧详情回到顶部，并提供上一条、下一条和下个需跟进的连续浏览按钮。
- 窄屏详情页标题栏改为可换行布局，Scenario列表继续以抽屉方式展开，避免导航和状态
  控件在移动宽度下互相挤压。
- 新增最终交付报告合并能力。核心实现位于
  `autowork_core.runtime.reporting.final_report`，支持基于普通Spark JSON创建最终报告、
  合并复跑结果、删除误合并结果以及重新渲染最终HTML。
- 宿主侧新增轻量入口`Bdd/final_report.py`。当前右键运行入口在对应方法中填写参数，
  在文件底部选择调用；不要寻找顶部`ACTION`配置块。最终HTML不显示“复跑后通过”、
  flaky或尝试次数，内部操作日志仍独立保留。
- 最终报告输出到`artifacts/final-reports/`，其中`autowork-final-report.json/html`为交付
  报告正文，`autowork-final-merge.json`只保存内部操作日志。合并时会把截图、录屏和调试
  附件快照到`artifacts/final-reports/assets/`，避免普通运行清理`reports/screenshots/recordings`
  后最终报告断链。
- 单次Spark报告仍输出到`artifacts/reports/autowork-report.html/json`并可在下一次运行前
  被清理；不可变Run Result快照仍保留在`artifacts/run-results/`。
- 本地 runner 新增完整 Scenario / Example 复跑入口：普通 Scenario 填 `scenario_name` 即可，
  Scenario Outline 不填 `example_id` 时复跑全部 Examples，填写 `example_id` 时只复跑对应行。
  复跑报告仍映射回原始 Feature 路径，便于最终报告合并。

### 1.1.0 升级操作

适用于将明确的框架发布源同步到宿主项目。以下操作保留宿主 `Bdd/` 和运行证据；
最终报告的当前调用方式独立维护，不以复制旧配置块代替接口核对。

1. 按当前发布源同步规则更新框架拥有目录：`autowork_core/`、顶层`config/`、顶层`ai/`、
  `docs/`、`.github/`、通用`resources/`以及根目录框架文件。
2. 不覆盖宿主业务`Bdd/`目录。若需要右键运行最终报告合并入口，可将发布源中的中性
   `Bdd/final_report.py`复制到宿主项目，或继续使用核心命令行入口：

   ```powershell
   python -m autowork_core.runtime.reporting.final_report --help
   ```

3. 全量运行后创建最终报告底稿；失败Feature或Scenario复跑后，再把复跑生成的普通报告
   合并进最终报告。输入选择、调用示例和结果核对见
   [当前最终报告的使用方法](#当前最终报告的使用方法)。不要整体覆盖宿主已自定义的入口。

4. 升级后在宿主根目录运行：

   ```powershell
   python -B -m autowork_core.utils.debug_tools.framework_smoke --project-root .
   ```

  只有宿主自己的`Bdd/`也发生变化时，才继续运行对应项目测试。顶层`config/`是框架
  Python包；项目运行配置固定为`Bdd/config.yaml`。

### 1.1.0 升级影响

- 最终报告合并是新增功能，不改变普通Spark报告路径和清理行为；旧的
  `artifacts/reports/autowork-report.html/json`仍只表示最近一次执行。
- `Bdd/final_report.py`属于宿主便捷入口。宿主已经自定义该文件时，不要直接覆盖；可只
  对齐默认路径、方法参数和底部调用，或直接调用核心模块。
- `autowork-final-merge.json`不是交付报告正文，只是内部操作日志。需要给外部查看时使用
  `autowork-final-report.html`。

## 1.0.0 - 2026-08-24

首个正式框架发布源版本，没有可直接升级的上一正式版本。
本条用于理解首次正式发布的资产边界，不把之前的开发里程碑当作受支持的降级目标。

### 1.0.0 主要变化

- 确立框架发布源与宿主项目边界：`autowork_core/`、顶层`config/`、顶层`ai/`、`docs/`、
  `.github/`和通用`resources/`由框架拥有；`Bdd/`和`artifacts/`由宿主拥有。项目运行配置
  固定为`Bdd/config.yaml`。
- 发布源保留中性`Bdd/`参考骨架；产品进程、Page、locator、data、供应商SDK和设备DLL
  不进入框架资产。
- Recorder生成入口收敛为Generation Profile、admission和内容寻址Generation Job；
  Job继续绑定Design、Plan、Transaction、Run Result和Oracle各自的权威结果。
- Spark支持结构化Run Result 1.3诊断及最终报告合并，失败分类、附件和生成provenance
  保持可追溯。
- `framework_validation/`保留在发布源中用于框架测试和评测，但不复制到宿主项目。

### 1.0.0 升级操作

适用于首次采用该正式发布源时的资产交接；不存在本文支持的上一正式版本降级路径。
同步后运行轻量检查，只有实际执行过的宿主测试才构成相应行为验证。

1. 先备份宿主自己的`Bdd/`和需要保留的`artifacts/`证据。
2. 完整替换`autowork_core/`、顶层`config/`、顶层`ai/`、`docs/`、`.github/`、`resources/`以及根目录
   `requirements.txt`、`behave.ini`、`README.md`、`.gitattributes`和`.gitignore`。
3. 保留宿主的`Bdd/`目录，不把`framework_validation/`复制到宿主项目。
4. 使用`APP_PATH: runtime`的宿主必须实现`Bdd.application.start_application()`和
   `stop_application()`；中性模板会失败关闭，不会假装已启动应用。
5. 在宿主根目录运行：

   ```powershell
   python -B -m autowork_core.utils.debug_tools.framework_smoke --project-root .
   ```

只有宿主自己的`Bdd/`同时发生变化时，才继续运行对应项目测试。录制证据
跨项目或跨机器迁移应使用Recorder便携包，不把`artifacts/`直接当作框架配置覆盖。

## 2026-08-23开发里程碑（未正式发布）

以下仅保留历史实现变化背景，不是当前环境可直接执行的升级/降级步骤，也不要求
当前调用者采用当时的协议或生成入口。

### 2026-08-23 开发变化

- 收紧Root、Child和XPath文本语义，生成代码使用严格`$loc:`引用，隐式OCR回退退出
  当前路径。
- Request采用业务身份并与Framework Contract演进解耦；运行授权由显式Execution
  Profile提供。
- Run Result 1.3加入结构化Runtime Diagnostic，区分未找到、状态超时、视觉未命中和
  backend错误，并绑定当前Transaction代码快照。
- Decision媒体、locator候选和独立Oracle加强内容摘要、路径和运行身份校验。

### 2026-08-23 历史影响

- 依赖裸locator名称或隐式OCR的生成代码需要改为显式`$loc:`或声明OCR locator。
- 未绑定当前Request、Plan和Transaction的旧Run Result只能作为历史报告，不能升级
  当前生成质量状态。
