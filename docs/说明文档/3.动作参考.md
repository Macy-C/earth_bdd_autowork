# 3. 动作参考
文档哈希（SHA256）：`52c2599f8634661ab905fa2a73cb0cf2a637ce43420b36b40309e672b2b56d8b`

本文档记录框架可通过 WindowPage/WindowView 调用的通用动作。README 只保留框架规则和工程标准，具体动作 API 统一放在这里维护。

按任务选择：先查 API 总表定位方法，再阅读对应小节的参数、返回值、失败行为和限制。
API 可调用不代表适合所有控件；正式脚本的分层约束见
[2.编写自动化脚本](2.编写自动化脚本.md)。

| 当前意图 | 优先查询 | 必须保留的判断 |
| --- | --- | --- |
| 激活或操作目标 | 点击和焦点、输入和键盘 | 目标属于哪个窗口；调用完成不等于业务提交完成 |
| 设置选中、展开或数值状态 | 有状态控件 | 控件类型、UIA Pattern 和最终状态是否满足 |
| 等待 UI 条件 | 等待 | 布尔返回值是否为 `True`；UI 状态是否足以支持下一步 |
| 读取或保存本次值 | 读取信息、Scenario 变量 | 对象、属性、返回类型和读取时点是否正确 |
| 判定结果 | 普通断言、OCR/图片断言 | 预期来源独立，不能把未命中或错误对象当成功 |
| 使用视觉识别或坐标 | OCR、图片、拖拽和滚动 | 结构定位是否不足、Region 是否正确、位置是否仍适用 |

## 调用入口

业务窗口页面继承 `WindowPage`，测试代码通过其继承的 `BasePage` 方法调用动作：

```python
from autowork_core.page import WindowPage


class CustomerPage(WindowPage):
    root_locator_file = "customer/right_screen.yaml"
    root_locator = "customer_window"
    data_file = "customer_data.yaml"

    def search_customer(self, customer_name):
        self.input_text("$customer_search_input", customer_name)
        self.click("$search_button")
        self.wait_visible("$customer_list")
```

底层函数位于 `autowork_core/actions/`，Step 不直接导入这些函数。Step 可以通过
`get_page()` 获得的 WindowPage/WindowView 调用 BasePage API，实现首次出现或场景特有
的线性流程；locator 必须是所属窗口包中的严格引用。稳定复用流程才提取为页面业务方法。

维护者新增公开 `BasePage` 方法时，必须同时在 `AI_CAPABILITIES` 中显式分类。只有
`plan_enabled=True` 的动作会成为AI Plan operation；`plan_enabled=False` 只允许AI在Page
实现中作为辅助API调用，仅调试和策略禁止接口不向生成开放。所有类别都必须登记，
Generation Contract会拒绝任何未分类或已失效的公开方法。

## 参数约定

| 参数 | 说明 |
| --- | --- |
| `locator_or_name` | `$name` / `$loc:name` 表示 locator 引用；不带 `$` 的字符串按 legacy 临时结构 locator 处理；也可传 dict locator |
| `data_or_name` | `$name` / `$data:name` 表示 data 引用；不带 `$` 的字符串按直接文本处理 |
| `text` / `expected` | OCR 文本或断言期望文本；引用资源时使用 `$loc:name` / `$data:name` |
| `region` | 限定视觉识别区域，可传 `$locator`、locator dict、矩形 dict 或 `(left, top, width, height)` |
| `wait_type` | UIA 目标等待条件，可选 `None`/`none`、`exists`、`visible`、`enabled`、`ready` |
| `wait_timeout` | Child/XPath 目标出现并达到等待条件的总上限，单位秒 |
| `visual_timeout` | OCR/PIC/坐标等视觉定位等待上限，单位秒 |
| `timeout` | 显式 wait、断言、OCR/PIC 动作的等待上限，单位秒 |
| `interval` | 轮询间隔，单位秒 |
| `msg` | 自定义断言失败信息 |
| `variable_name` | 当前 Scenario 内的 ASCII 变量名，必须匹配 `[A-Za-z_][A-Za-z0-9_]{0,63}` |
| `overwrite` | 是否允许覆盖当前 Scenario 中已存在的同名变量，默认 `False` |
| `allow_empty` | 是否允许保存 `None` 或空字符串，默认 `False` |

资源引用必须显式使用 `$`。不带 `$` 的字符串不会自动查 locator/data，而是按临时 locator 或直接文本处理：

| 写法 | 含义 |
| --- | --- |
| `$save_button` | 在 locator 参数中严格引用 locator；在 data 参数中严格引用 data；在 OCR 文本中自动查 locator/data |
| `$loc:save_button` | 强制严格引用 locator |
| `$data:customer_name` | 强制严格引用 data |
| `$$100` | 字面量 `$100` |

严格引用找不到 key 会立即报错；`$name` 在 OCR 文本中同时命中 locator 和 data 时会报歧义，请改用 `$loc:name` 或 `$data:name`。

无前缀临时 locator 只按 `auto_id`、Accessible Name 依次做精确结构查询，并记录
legacy迁移警告；结构查询失败会直接报错，不再隐式切换到OCR。视觉定位必须显式使用
OCR/PIC locator并限定`region`。

## Scenario 变量

适用于运行时取得的基线、对象身份或其他跨 Step 数据。输入是本次实际读取值，输出为
当前 Scenario 的变量；它不是静态 YAML data，也不是跨场景持久化存储。

Scenario 变量用于把运行时读取结果显式传给当前 Scenario 的后续 Step。变量保存在
`context.autowork_scenario.variables`，不写入静态 YAML data，也不会跨 Scenario 保留。
任意 Page/View 实例都访问当前 Scenario 的同一变量集合：

```python
@when("记录当前订单编号")
def step_impl(context):
  page = get_page(context, OrderPage)
  page.save_text("$order_id", "order_id")


@then("可以按该订单编号查询")
def step_impl(context):
  page = get_page(context, SearchPage)
  page.input_text("$search_input", page.get_variable("order_id"))
```

`save_text()`复用`get_text()`的控件值和可访问文本读取规则；`save_attr()`复用
`get_attr()`，不另建控件读取规则。`0`和`False`会原样保存，只有`None`和空字符串
默认视为空值。重复变量名默认失败，确需更新时显式传`overwrite=True`；确需保存空值
时显式传`allow_empty=True`。

Scenario变量没有`$variable`引用语法；`$name`和`$data:name`仍只表示静态data。
变量API的调用日志只记录变量名和策略，不记录保存值。`save_text()`和`save_attr()`可由
Recorder Plan 4.1在F9 Observation证据支持时生产`result_binding`；后续operation通过
`source=runtime.<binding>`消费。`get_variable()`只作为生成代码的实现辅助，
`set_variable()`不向Recorder Plan开放。框架校验同Scenario内唯一、先生产后消费、至少
一个consumer及Plan-to-Code调用闭包，但不会按值相同或Step相邻自动建立业务关系。

## 定位等待策略

框架现在把 UIA 等待和视觉等待拆开，避免所有动作都走较重的 `ready` 判断。

| 参数 | 控制范围 | 说明 |
| --- | --- | --- |
| `wait_type` | UIA 目标条件 | `exists` 等目标出现，`visible` 等出现且可见，`enabled` 等出现且可用，`ready` 等出现、可见且可用；`None`/`none`/`off`/`0` 只探测一次 |
| `wait_timeout` | UIA 目标等待 | 控制 Child/XPath 目标出现并达到 `wait_type` 的总等待上限，不影响 OCR/PIC 轮询 |
| `visual_timeout` | 视觉定位等待 | 主要影响 OCR/PIC/坐标等视觉定位；普通 UIA child/xpath 通常不用改 |
| `timeout` / `interval` | 显式 wait、断言、视觉动作 | `wait_exists()`、`assert_exists()`、`wait_pic_present()` 等使用这个旧口径 |

默认策略：

| 动作 | 默认等待 | 原因 |
| --- | --- | --- |
| `click()` / `double_click()` / `right_click()` / `focus()` | `wait_type="visible"` | 点击类动作只需要目标可见；`Thumb`、`Text`、`Custom` 等控件经常不适合强制 `enabled` |
| `input_text()` / `send_text_keys()` / `clear_text()` | `wait_type="enabled"` | 输入类动作通常需要控件可编辑或可接收键盘 |
| `wait_ready()` | 显式 `ready` | 只在确实需要“可见且可用”的同步点使用 |
| OCR/PIC 动作 | `timeout` / `interval` | 视觉识别有独立轮询，不使用 `wait_type` |

常见选择：

```python
self.click("$save_button")                         # 默认 visible，速度更稳
self.click("$submit_button", wait_type="enabled") # 点击前必须等按钮解禁
self.wait_ready("$main_window", timeout=15)        # 明确需要 ready 时显式等待
self.click("$static_text", wait_type="exists")     # Text 控件只要求存在
```

## `root` 和 `region` 的选择

`root` 只引用顶层窗口，用于 Child/XPath 元素定位。`region` 引用普通 Child/XPath locator，只影响 OCR/PIC 的截图范围。

推荐顺序：

| 场景 | 推荐写法 |
| --- | --- |
| 长期维护的图片/OCR locator | 在 locator 中写 `region` |
| 临时调试、临时缩小截图范围 | 调用动作时传 `region` |
| 同一个模板偶尔要在不同区域找 | 模板条件保持不变，每次传不同 `region` |

如果 OCR/PIC locator 自带 YAML `region`，动作调用时又传了 `region`，则动作参数优先，只覆盖本次截图范围。
命名 Region 必须唯一匹配普通 Child/XPath 元素并取得有效矩形；匹配多个元素时抛出
`ElementAmbiguousError`，不使用第一个候选。先修正区域身份，再调整识别参数。

```python
# 默认使用 save_icon locator 中配置的 region
self.wait_pic_present("$save_icon")

# 本次调用临时改为只在 dialog_window 区域搜索
self.wait_pic_present("$save_icon", region="$dialog_window")
```

## 点击和焦点

本组方法用于已确认窗口范围内的交互。正式脚本使用所属 Page/View 的 `$loc:` 引用，
查询或交互失败应向调用者暴露；没有异常只说明动作按接口完成，不证明保存、扫描等业务结果。

### 单击与按住目标 click

接口：`click(locator_or_name, offset_x=None, offset_y=None, wait_type="visible", wait_timeout=5, visual_timeout=10, *, hold_duration=None)`。

单击目标。目标可以是普通 UIA 控件，也可以是 OCR、图片或坐标 locator 返回的点。
默认只等待目标可见，避免对 `Text`、`Thumb`、`Custom` 等控件误用 `ready` 或 `enabled` 导致慢和误失败。
Child/XPath 目标尚未进入 UIA 树时，`click()` 会在 `wait_timeout` 内重新查询；不需要先调用一次 `wait_visible()`。

`hold_duration` 是仅关键字参数，接受整数或浮点秒数。默认 `None` 或 `0` 保持原有普通点击；正数执行一次按下、保持、抬起，适用于控件、OCR、图片和坐标目标。保持时长是最少等待时间，系统调度及 pywinauto 内部等待可能使实际时间更长，不保证精确毫秒，也不代表点击后的业务等待。负数、布尔值、非数字、NaN 和无穷大会在定位前被拒绝。

控件内偏移 `offset_x/offset_y` 必须同时提供，且为目标矩形内的整数坐标；坐标型目标不能叠加控件内偏移。保持期间不重新定位，按下和抬起使用同一桌面坐标，中途异常也尝试释放并向上传递失败。此参数不适用于 `double_click` 或 `right_click`，不会触发额外激活、重试或改变全局输入时序。

```python
self.click("$save_button")
self.click("$submit_button", wait_type="enabled", wait_timeout=10)
self.click("$save_by_ocr")
self.click("$loc:Scan_button", hold_duration=0.15)
self.click("$loc:Scan_button", offset_x=5, offset_y=8, hold_duration=0.15)
```

内联 locator 属于临时调试，不混入上面的正式资源调用示例；写法见
[编写自动化脚本：临时调试](2.编写自动化脚本.md#临时调试内联-locator)。

### 双击目标 double_click

接口：`double_click(locator_or_name, wait_type="visible", wait_timeout=5, visual_timeout=10)`。

对命名目标执行双击，默认等待可见；目标必须属于当前窗口包。双击完成不保证详情页
已打开，后续页面或对话框应另有明确等待与验证。

```python
self.double_click("$customer_row")
```

### 右键与菜单 right_click

接口：`right_click(locator_or_name, wait_type="visible", wait_timeout=5, visual_timeout=10)`。

对目标执行右键，默认等待可见。弹出的菜单项仍需命名 locator 和出现等待，不用固定
延时假定菜单已经打开；菜单所属窗口由 Page 资源规则决定。

```python
self.right_click("$customer_row")
self.click("$delete_menu_item")  # 菜单项由 click 自身等待出现并可见
```

### 聚焦控件 focus

接口：`focus(locator_or_name, wait_type="visible", wait_timeout=5, visual_timeout=10)`。

让目标获取焦点。坐标型目标会先点击目标点；普通控件优先调用 `set_focus()`，失败时退回点击。

```python
self.focus("$name_input")
```

聚焦可能包含点击，因此不是无副作用的控件属性检查。仅需读取值时使用读取 API，
不要为获得焦点而隐含改变选中状态。

### 前置窗口 bring_to_front

接口：`bring_to_front(locator_or_name, wait_type="exists", wait_timeout=5, visual_timeout=10, activate=False)`。

将目标窗口或控件前置并聚焦。普通目标会先尝试从最小化状态恢复，再调用 `set_focus()`；失败时退回 `click_input()`。坐标型目标会点击坐标点。
这个动作不会把窗口设置为 always-on-top，只用于测试步骤中显式激活目标窗口。

```python
self.bring_to_front("$main_window")
self.bring_to_front("$customer_search_input", wait_type="visible")
```

## 输入和键盘

本组方法要求目标能够接收输入；locator 必须解析到正确字段。`data_or_name` 为直接文本
或显式 data 引用，不从相同名称猜值。输入、清空、按键调用与业务提交是不同事件。

### 清空并输入文本 input_text

接口：`input_text(locator_or_name, data_or_name, use_paste=False, wait_type="enabled", wait_timeout=5, visual_timeout=10)`。

输入文本。默认会清空原内容。
输入类动作默认等待目标可用；如果目标是坐标、OCR/PIC 或特殊控件，可按实际情况改成 `visible`、`exists` 或 `None`。

```python
self.input_text("$name_input", "$customer_name")
self.input_text("$remark_input", "hello world")
self.input_text("$long_text_input", "$long_text", use_paste=True)
self.input_text("$custom_editor", "text", wait_type="visible")
```

执行策略：

| 目标类型 | 策略 |
| --- | --- |
| 坐标型目标 | 点击坐标，`Ctrl+A` 清空，再发送键盘或粘贴 |
| 标准 Edit 控件 | 优先 `set_edit_text()` |
| 其他控件 | 点击后 `type_keys()`，失败后退回全局 `SendKeys` |

`use_paste=True` 适合长文本、特殊字符或中文输入更稳定的场景。

字段需要 Enter、失焦或保存才能生效时，由场景按产品依据执行提交，并读取生效后的值；
不要从调用返回推断产品已经接受输入。

### 清空输入框 clear_text

接口：`clear_text(locator_or_name, wait_type="enabled", wait_timeout=5, visual_timeout=10)`。

对已定位的输入目标执行清空，默认等待可用。清空不等于恢复全部表单或测试数据，
必要时读取字段或执行对应断言确认结果。

```python
self.clear_text("$name_input")
```

### 发送按键 send_text_keys

接口：`send_text_keys(locator_or_name, data_or_name, wait_type="enabled", wait_timeout=5, visual_timeout=10)`。

聚焦目标后发送按键字符串，适合 `{ENTER}`、`^a`、快捷键等。
输入是按键语法，不是无条件的字面文本；执行后仍应检查操作对应的状态或业务结果。

```python
self.send_text_keys("$name_input", "{ENTER}")
self.send_text_keys("$name_input", "^a{BACKSPACE}")
```

## 有状态控件

| 目标状态 | API | locator 指向 | 关键边界 |
| --- | --- | --- | --- |
| CheckBox 选中或取消 | `set_checked` | CheckBox 本身 | 使用目标布尔状态，不盲目 toggle；indeterminate 失败 |
| 选择选项或页签 | `select_radio` / `select_tab` | RadioButton / TabItem | 要求对应 UIA Pattern 并验证选中结果 |
| 选择集合成员 | `select_list_item` / `select_tree_item` | ListItem/DataItem / TreeItem | 不是集合父容器，不证明该项业务身份正确 |
| 展开或收起树节点 | `set_tree_expanded` | TreeItem | 展开与选择是不同状态 |
| 设置滑块数值 | `set_slider_value` | Slider | 核对 RangeValue 范围，不能用坐标变化冒充数值生效 |

有状态控件通常优先使用“设置最终状态”的语义动作，而不是重复`click()`。AI可结合
业务意图和Action Knowledge选择其他注册动作；这些API运行时仍要求相应UIA Pattern，
Pattern缺失、控件类型不匹配或最终状态未达到都会失败。

```python
self.set_checked("$enabled_checkbox", True)
self.select_radio("$absolute_mode_radio")
self.select_tab("$advanced_tab")
self.select_list_item("$patient_a_item")
self.select_tree_item("$advanced_node")
self.set_tree_expanded("$advanced_node", True)
self.set_slider_value(
  "$dose_slider",
  50,
  expected_minimum=0,
  expected_maximum=100,
)
```

`select_tab`、`select_list_item`和`select_tree_item`的locator指向录屏实际操作的
`TabItem`、`ListItem/DataItem`或`TreeItem`，不是父容器。这样Plan target仍由同一个
Action指纹授权。CheckBox处于indeterminate状态时`set_checked`会失败，不猜测循环toggle；
Tree展开/收起使用`set_tree_expanded`，与`select_tree_item`分开；Slider值必须在控件
RangeValue允许范围内，AI生成代码还会核对录制时冻结的最小值和最大值。

## 等待

本节 `wait_exists`、`wait_not_exists`、`wait_visible`、`wait_enabled`、`wait_ready`
和 `wait_exposed` 在条件满足时返回 `True`，超时未满足时返回 `False`；不能把调用结束
当成等待成功。查询异常的处理随具体入口而异，不承诺所有错误都会变成 `False`。
当该条件是后续动作的必要前提时，必须检查返回值或使用适用的断言 API：

```python
if not self.wait_visible("$loc:success_message", timeout=10):
  raise TimeoutError("成功提示未在规定时间内出现")
```

UI 状态只证明对应可观察条件，不自动证明后台任务或产品业务完成。

### 等待元素存在 wait_exists / wait_not_exists

接口：`wait_exists(locator_or_name, timeout=10, interval=0.5)`、`wait_not_exists(locator_or_name, timeout=10, interval=0.5)`。

输入为所属窗口中的命名目标。`wait_exists` 等元素存在，`wait_not_exists` 等元素消失；
条件满足返回 `True`，超时返回 `False`。元素存在不等于可见、可用或业务任务完成。

```python
opened = self.wait_exists("$dialog_window", timeout=10)
closed = self.wait_not_exists("$loading_mask", timeout=10)
```

`opened`、`closed` 是布尔结果；必要前提为 `False` 时应明确失败，不继续依赖后续动作。

### 等待元素可见 wait_visible

接口：`wait_visible(locator_or_name, timeout=10, interval=0.5)`。

输入为目标 locator；可见时返回 `True`，超时未满足返回 `False`。可见不意味着可用、
未被遮挡或结果数据已经完整加载；必要时选择更合适的观察条件。

```python
self.wait_visible("$success_message", timeout=10)
```

### 等待元素可用 wait_enabled

接口：`wait_enabled(locator_or_name, timeout=10, interval=0.5)`。

等待目标报告 enabled，满足返回 `True`，超时返回 `False`。按钮恢复可用本身不能
证明扫描、重建或保存成功，业务完成需要独立的状态或结果依据。

```python
self.wait_enabled("$submit_button", timeout=10)
```

### 等待可见且可用 wait_ready

接口：`wait_ready(locator_or_name, timeout=10, interval=0.5)`。

等待元素可见且可用。`ready` 比 `exists`、`visible` 更严格，也更容易在复杂 UIA 控件上变慢；只在真正需要可交互状态时使用。
条件满足返回 `True`，超时返回 `False`；不因此保证元素中心点未被其他窗口遮挡。

```python
self.wait_ready("$submit_button", timeout=10)
```

### 等待目标实际暴露 wait_exposed

接口：`wait_exposed(locator_or_name, timeout=10, interval=0.5)`。

等待元素可见且可用，并通过元素中心点的 UIA 屏幕命中父链确认目标当前实际暴露。
适合启动加载页或临时窗口可能覆盖旧页面，但旧页面控件仍留在 UIA 树并继续报告
`visible/enabled` 的同步点。无法取得目标矩形、屏幕命中元素或可靠身份时返回 `False`。

```python
self.wait_exposed("$main_page_button", timeout=10)
```

等待状态建议：

| 状态 | 适合场景 |
| --- | --- |
| `exists` | 窗口、弹窗、后台控件创建 |
| `visible` | 提示文本、结果展示、列表加载完成 |
| `enabled` | 按钮解禁、输入框可编辑 |
| `ready` | 确认控件既可见又可用，再执行强交互 |
| `exposed` | 页面切换期间确认控件既 ready，中心点也未被其他窗口覆盖 |

## 读取信息

本组方法只读取当前匹配对象，不自动建立患者、检查或前后结果的业务身份。读取之前
必须明确选中对象和时点；单值、列表、空值与查询错误不得混为“取得了正确数据”。

### 读取控件内容 get_text

接口：`get_text(locator_or_name, first_only=True)`。

读取控件内容。优先读取 UIA Value Pattern，再尝试 `get_value()`、Legacy Value，
随后才尝试 `window_text()`、`texts()`、`element_info.name`，避免把输入框标签当成正文。
已取得的 Value 即使是空字符串也会作为内容返回，不再用非空名称覆盖。

```python
actual = self.get_text("$result_label")
texts = self.get_text("$loc:result_rows", first_only=False)
```

默认按单目标语义返回字符串；`first_only=False` 返回匹配元素的文本列表，不承诺目标
唯一。单个元素未读到内容时返回空字符串。坐标型目标不支持读取文本；查询失败不能
仅凭该返回约定推断为空值。需要控件 Accessible Name 而非正文时，使用 `get_attr(..., "name")`。

### 读取控件属性 get_attr

接口：`get_attr(locator_or_name, attr_name, timeout=3, default=None, first_only=True)`。

读取控件属性。默认返回单目标属性；`first_only=False` 返回属性列表。属性值保留实际
类型，不统一转换为字符串；未取得属性时使用 `default`。

```python
name = self.get_attr("$save_button", "name")
enabled = self.get_attr("$save_button", "enabled", default=False)
value = self.get_attr("$name_input", "value")
```

常用属性：

| 属性 | 说明 |
| --- | --- |
| `name` / `title` / `text` | 同一 Accessible Name 属性的别名，不是输入框正文 |
| `value` | 输入框值或 ValuePattern 值 |
| `class_name` | 控件 class name |
| `control_type` | UIA 控件类型 |
| `automation_id` / `auto_id` | AutomationId |
| `enabled` | 是否可用 |
| `visible` | 是否可见 |
| `handle` | 句柄 |
| `coords` | 坐标型目标返回坐标 |

`selection` 返回选中项名称列表，`value` / `value.value` 读取 Value Pattern；具体类型、
空选择与使用示例见 [4.定位器与配置：selection](4.定位器与配置.md#selection)。

### 按顺序读取集合 get_collection_items

接口：`get_collection_items(locator_or_name, timeout=5, max_items=200)`。

按UI树直接子项顺序读取集合文本，排除ScrollBar chrome。目标必须是结构化UI元素，
`max_items`必须是非布尔正整数；子项数量超过上限时失败，不返回截断结果。

```python
items = self.get_collection_items("$phase_list")
```

## 普通断言

输入由目标 locator、所需状态或可信预期组成；断言未满足会失败，不以 `False` 表示
“仍可继续”。预期中的 `$data:` 是静态数据引用，运行时基线则显式从 Scenario 变量读取。

### 存在和状态断言

用途是验证元素的存在性、可见性或可用性，不验证业务对象归属。不存在断言只能接受
正常未命中，不能把非法 Root、歧义或后端错误当作元素不存在。

```python
self.assert_exists("$save_button", timeout=5)
self.assert_not_exists("$loading_mask", timeout=2)
self.assert_visible("$success_message", timeout=5)
self.assert_not_visible("$loading_mask", timeout=2)
self.assert_enabled("$submit_button", timeout=5)
self.assert_disabled("$submit_button", timeout=5)
```

| 方法 | 判断 |
| --- | --- |
| `assert_exists` | 元素应存在 |
| `assert_not_exists` | 元素不应存在 |
| `assert_visible` | 元素应可见 |
| `assert_not_visible` | 元素不应可见 |
| `assert_enabled` | 元素应可用 |
| `assert_disabled` | 元素应不可用 |

### 文本断言

输入为命名目标和期望字符串，使用框架文本读取规则比较。需要判断字段名称而非内容时，
不要复用同一个文本断言假设，应选择明确的属性读取或属性断言。

```python
self.assert_text_equal("$result_label", "$expected_result")
self.assert_text_contains("$message_label", "保存成功")
self.assert_text_not_contains("$message_label", "Error")
self.assert_text_empty("$remark_input")
```

`expected` 不带 `$` 时按直接文本处理；需要引用 data 时使用 `$expected_result` 或 `$data:expected_result`。

### 属性断言

输入为目标、属性名和预期值；属性相等按相应值比较，不能把列表或布尔值预先转成显示
字符串。若属性未支持或读错目标，先查读取证据，不靠改预期使断言通过。

```python
self.assert_attr_equal("$save_button", "enabled", True)
self.assert_attr_contains("$name_input", "value", "张三")
```

属性断言适合文本不稳定但 UIA 属性可靠的控件。

### 集合断言

输入为结构化集合与预期 `list` / `tuple`。只比较该集合直接子项的有序文本，超限失败；
不会自动识别哪些项是本次新产生的业务结果。

```python
self.assert_collection_equal(
  "$phase_list",
  ["Phase 250 ms", "Phase 350 ms"],
  max_items=200,
)
```

`expected`必须解析为`list`或`tuple`。断言按顺序精确比较，不排序、不忽略重复项；读取目标
不是结构化元素或超过`max_items`时失败关闭。

## OCR 视觉动作

OCR 底层能力在 `autowork_core/common/ocr_engine.py`，动作层在 `autowork_core/actions/visual_actions.py`。

使用前确认结构定位确实不足、目标文字可见且 Region 指向正确窗口区域。OCR 结果是图像
识别观察，不是 UIA 控件身份；误识别不能靠反复降低匹配要求变成正确业务对象。

视觉参数优先级统一为：调用时显式参数 > locator 中的覆盖参数 > `Bdd/config.yaml` 默认参数 > `MODE` 预设默认值。OCR 模型仍然只初始化一次；动态覆盖的是每次 `predict()` 调用的检测参数。

正式窗口包中的 OCR locator 需同时声明目标文本和本地 `region`。下例假设 `main_window`
已由 Page 声明；`main_content` 是可唯一取得矩形的结构 locator，不是 OCR 控件：

```yaml
main_content:
  root: main_window
  by: xpath
  value: "//Pane[@auto_id='MainContent']"

save_by_ocr:
  by: ocr
  value: Save
  region: main_content
```

也可以对单个 locator 覆盖适合动态调整的参数：

```yaml
small_save_by_ocr:
  by: ocr
  value: Save
  region: main_content
  match_mode: exact
  index: 0
  det_unclip_ratio: 1.8
  det_box_thresh: 0.65
```

| 参数 | 适合位置 | 作用 |
| --- | --- | --- |
| `match_mode` | locator | `smart` 先精确再包含，`contains` 包含匹配，`exact` 精确匹配 |
| `index` / `found_index` | locator | 多个命中候选时选择第几个 |
| `det_unclip_ratio` | locator | 检测框外扩比例；文字被裁掉时调大，文字粘连时调小 |
| `det_box_thresh` | locator | 检测框阈值；降低可减少漏检，升高可减少误检 |
| `det_limit_side_len` | 少量 locator | 检测输入尺寸；越大越可能识别小字，但更慢 |
| `cache_ttl` / `use_cache` | locator 的 `cache_ttl`；读取 API 的 `use_cache` | 短时复用 OCR 结果；动态页面谨慎使用 |
| `timeout` / `interval` | action/locator | 等待上限和轮询间隔；未写时走 `OCR_SETTING` |

`mode`、`warmup`、`recognition_batch_size` 属于全局运行或初始化策略，不建议写进 locator。
表中 locator 覆盖项不是任意公开方法都接受的关键字参数；动作参数以各 API 的签名为准。

### 读取区域文字 get_ocr_text

接口：`get_ocr_text(region=None, timeout=None, joiner=" ", use_cache=False)`。

输入为当前区域及拼接分隔符，输出为识别到的非空文字按 `joiner` 拼接的字符串。没有
识别文字时可能得到空字符串，不能据此认定屏幕上没有文字；先检查区域和识别证据。

```python
text = self.get_ocr_text(region="$loc:main_content", joiner="\n", use_cache=False)
```

### 按正则提取 OCR 内容 extract_ocr_regex

接口：`extract_ocr_regex(pattern, region=None, timeout=None, flags=None, required=True, joiner=" ", use_cache=False)`。

先读取区域文本，再用正则提取。命中返回包含捕获组及 `_text`、`_match` 的字典；无命中
且 `required=True` 时断言失败，`required=False` 时返回 `None`。正则命中仍需核对字段
含义、单位和对象，不把数字形式相似当作同一业务值。

```python
reading = self.extract_ocr_regex(
  r"(?P<value>\d+)\s*ms",
  region="$loc:main_content",
  required=True,
)
```

### 等待 OCR 文字出现 wait_ocr_text_present

接口：`wait_ocr_text_present(text, timeout=None, interval=None, region=None)`。

输入为文字或严格 OCR locator 引用，并限定当前 Region。识别到目标返回 `True`，
等待未满足返回 `False`；必要条件必须检查该布尔值，不用调用结束代替命中。

```python
self.wait_ocr_text_present("保存成功", region="$loc:main_content", timeout=10)
self.wait_ocr_text_present("File", region="$notepad_window", timeout=10)
self.wait_ocr_text_present("$small_save_by_ocr")
```

### 等待 OCR 文字消失 wait_ocr_text_absent

接口：`wait_ocr_text_absent(text, timeout=None, interval=None, region=None)`。

在同一正确区域内等待目标不再被识别，满足返回 `True`，超时返回 `False`。识别区域错
或漏检也可能表现为未命中，因此消失结论必须结合可信 Region 和产品观察条件使用。

```python
self.wait_ocr_text_absent("加载中", region="$loc:main_content", timeout=10)
```

### 断言 OCR 文字存在 assert_ocr_contains

接口：`assert_ocr_contains(text, timeout=None, region=None, msg=None)`。

在指定区域断言目标文字存在；未达到条件抛出断言错误，可用 `msg` 说明业务失败。
它不是可忽略返回值的等待，也不保证识别到的文字属于正确业务对象。

```python
self.assert_ocr_contains("Customer Directory", region="$main_window")
```

### 断言 OCR 文字不存在 assert_ocr_not_contains

接口：`assert_ocr_not_contains(text, timeout=None, region=None, msg=None)`。

断言当前指定区域不包含目标文字，仍存在时失败。先证明 Region 和识别方式适用，
不能用错误区域、错误语言或 OCR 漏检证明“没有错误提示”。

```python
self.assert_ocr_not_contains("Error", region="$loc:main_content", timeout=5)
```

### OCR 相对定位

接口：`get_ocr_relative_position(text, direction="right", offset=20, timeout=None, region=None)`
返回锚点相对位置；`click_ocr_relative` 使用相同参数计算位置并点击。输入必须是实际
可识别的锚点及方向、偏移；相对点不是目标控件身份，画面布局改变后须重新核对。

把 OCR 文本当作锚点，点击它附近的位置。锚点仍然写成普通 OCR locator，偏移在 action 层完成。

```yaml
customer_form:
  root: main_window
  by: xpath
  value: "//Pane[@auto_id='CustomerForm']"

name_label:
  by: ocr
  value: 姓名
  region: customer_form
```

```python
self.click_ocr_relative("$name_label", direction="right", offset=20)
```

方向支持：`right`、`left`、`down`、`up`、`center`，也支持常用中文方向。

### 保存 OCR 调试图 save_ocr_debug_image

接口：`save_ocr_debug_image(text=None)`。

按当前画面与可选目标文字保存调试材料，用于核对截图区域、候选和识别结果；保存成功
不代表目标文字识别成功，也不替代断言。

```python
self.save_ocr_debug_image("保存成功")
```

启用相应失败调试输出时，OCR 等待、断言、相对定位失败会保存调试图到
`artifacts/screenshots/ocr_*.png`；调试图是排障证据，不是业务通过记录。

## 图片视觉动作

图片识别底层能力在 `autowork_core/common/pic_engine.py`。模板默认从 `Bdd/data/` 读取，不写扩展名时自动补 `.png`。

前提是模板文件可读取、缩放与显示条件适用、Region 已绑定正确区域。识别产生的是图像
候选或位置，不是 UIA 对象；图片出现或消失需要与业务对象和时点结合解释。

### 图片条件写法

推荐 locator dict：

```yaml
save_icon:
  by: pic
  file: save_button.png
  region: main_content
  pos: 5
  threshold: 0.75
  method: mstpl
  rgb: true
```

以下内联 dict 仅供临时调试；`main_content` 假设已在当前窗口包中声明。正式脚本使用
上面的 YAML locator 和 `$loc:save_icon` 引用：

```python
self.assert_pic_exists({
    "by": "pic",
    "file": "save_button.png",
    "region": "$loc:main_content",
    "threshold": 0.75,
    "method": "mstpl",
    "pos": 5,
})
```

参数默认值：

| 参数 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `file` / `value` | 是 | 无 | 模板文件名或绝对路径 |
| `region` | 窗口包必填 | 兼容入口未限定时为全屏 | YAML 中引用普通 Child/XPath locator；动作参数还可按 API 传矩形区域 |
| `pos` | 否 | `PIC_SETTING.POS` | 返回模板上的目标点，`5` 为中心 |
| `threshold` / `confidence` | 否 | `PIC_SETTING.THRESHOLD` | 匹配阈值，越高越严格 |
| `method` | 否 | `PIC_SETTING.METHOD` | 可选 `mstpl`、`tpl`、`gmstpl`、`sift`、`brisk`、`akaze`、`orb`、`kaze`、`surf`、`brief`；空值使用 Airtest 默认策略 |
| `rgb` | 否 | `PIC_SETTING.RGB` | 是否启用颜色匹配 |
| `index` / `found_index` | 否 | 不传 | 显式传入时启用多候选选择，按屏幕从上到下、从左到右排序；不传时保持最佳命中快路径 |
| `timeout` | 否 | `PIC_SETTING.TIMEOUT` | 当前图片等待上限 |
| `interval` | 否 | `PIC_SETTING.INTERVAL` | 轮询间隔，越小越灵敏但 CPU 占用更高 |
| `debug_on_fail` | 否 | `PIC_SETTING.DEBUG_ON_FAIL` | 失败时是否保存图片调试图 |
| `scale_max` / `scale_step` | 否 | `PIC_SETTING` | 多尺度匹配参数，主要影响 `mstpl/gmstpl` 的速度和容错 |

图片 `index` 只在显式写入时启用多候选路径，未写 `index` / `found_index` 的图片定位速度和原逻辑一致。多候选能力依赖 Airtest 当前匹配方法，推荐优先配合 `method: tpl` 和较小 `region` 使用；OCR/PIC locator 不支持 `root`。

### 等待图片出现 wait_pic_present

接口：`wait_pic_present(pic_or_name, timeout=None, interval=None, region=None)`。

输入为严格图片 locator 引用或模板条件；在正确区域命中返回 `True`，未满足返回
`False`。裸模板名只在图片 API 中解释为模板，不能套用普通点击的裸 locator 语义。

```python
self.wait_pic_present("$save_icon", timeout=10)
self.wait_pic_present("111", region="$notepad_window", timeout=10)
```

### 等待图片消失 wait_pic_absent

接口：`wait_pic_absent(pic_or_name, timeout=None, interval=None, region=None)`。

等待指定区域内不再命中模板，满足返回 `True`，超时返回 `False`。模板失配、区域错误
或显示变化不是业务对象确实消失的充分证明。

```python
self.wait_pic_absent("$loading_icon", timeout=10)
```

### 断言图片存在 assert_pic_exists

接口：`assert_pic_exists(pic_or_name, timeout=None, region=None, msg=None)`。

命中指定区域中的目标模板时通过，等待未满足则断言失败。匹配到相似图形不自动证明
患者、页面或结果身份正确，必须使用适用模板与区域。

```python
self.assert_pic_exists("$save_icon")
```

### 断言图片不存在 assert_pic_not_exists

接口：`assert_pic_not_exists(pic_or_name, timeout=None, region=None, msg=None)`。

指定模板仍存在时断言失败；必须先确认模板和 Region 有效，不能通过换成不匹配模板
或错误截图区域让不存在断言通过。

```python
self.assert_pic_not_exists("$error_icon")
```

### 取得图片矩形 get_pic_region

接口：`get_pic_region(pic_or_name, timeout=None, region=None, padding=0)`。

输入是图片目标和可选外扩像素，输出为 `left/top/width/height` 矩形字典。未取得图片
候选或有效边界时失败，不返回伪造区域；该矩形不是窗口 Root 或永久定位身份。

```python
panel_region = self.get_pic_region("$panel_title", padding=8)
```

返回示例：

```python
{"left": 100, "top": 80, "width": 240, "height": 60}
```

### 图片相对定位

接口：`get_pic_relative_position(pic_or_name, direction="right", offset=20, timeout=None, region=None)`
返回相对坐标；`click_pic_relative` 使用相同参数计算并点击。前提是锚点模板和当前布局
适用；偏移位置本身不能证明落在正确业务控件上。

把图片模板当作锚点，点击它附近的位置。锚点仍然写成普通图片 locator，偏移在 action 层完成。

```yaml
main_content:
  root: main_window
  by: xpath
  value: "//Pane[@auto_id='MainContent']"

label_icon:
  by: pic
  file: label_icon.png
  region: main_content
```

```python
self.click_pic_relative("$label_icon", direction="right", offset=20)
```

### 保存图片调试图 save_pic_debug_image

接口：`save_pic_debug_image(pic_or_name)`。

输入为模板或严格图片 locator 引用，结果是用于核对区域与候选的本地图像，不会因此
认定模板命中或场景通过。

```python
self.save_pic_debug_image("$save_icon")
```

启用相应失败调试输出时，图片等待、断言、相对定位失败会保存调试图到
`artifacts/screenshots/pic_*.png`。找不到模板时先核对截图区域、窗口和模板文件。

## 窗口、拖拽和滚动

本组操作会影响窗口、焦点或画面位置。正式脚本先确认 Page 所有权及当前对象；不要
通过换 Root、改变滚动或固定坐标掩盖定位歧义。

### 临时指定窗口 set_root

接口：`set_root(root, name=None)`。

临时调试时显式设置当前顶层窗口。长期脚本应在 locator YAML 中声明 Root，并通过
WindowPage 使用；不要依赖运行时 `set_root()` 建立正式页面所有权。

```python
self.set_root({"class_name": "Notepad"}, name="Notepad_window")
```

### 相对拖拽 drag_by_offset

接口：`drag_by_offset(target, delta_x, delta_y, wait_type="enabled", wait_timeout=5, visual_timeout=10)`。

从结构化源元素中心拖到相对位移。`delta_x`和`delta_y`必须是非布尔整数，且不能同时为0；
坐标/OCR/PIC点不能充当拖拽源。返回目标坐标`(x, y)`。

```python
self.drag_by_offset("$phase_item", delta_x=390, delta_y=1)
```

### 垂直与水平滚动 scroll_to

接口：`scroll_to(target=None, direction="down", steps=1, wait_type="visible", wait_timeout=5, visual_timeout=10)`。

垂直方向发送鼠标滚轮事件。水平滚动必须传入水平`ScrollBar`或其`Thumb`，且控件
必须公开可写的RangeValue Pattern；框架按`SmallChange * steps`计算目标值并在范围内
截断，设置后回读验证。目标类型、方向或RangeValue不满足契约时立即失败，不降级为
方向按钮、Win32消息或水平滚轮。
传目标时默认只等目标可见，避免滚动条 `Thumb` 等控件因为 `enabled` 状态不稳定而误失败。

```python
self.scroll_to(direction="down", steps=3)
self.scroll_to("$customer_list", direction="up", steps=2)
self.scroll_to("$horizontal_scrollbar", direction="right", steps=3)
self.scroll_to("$horizontal_scrollbar", direction="left", steps=2)
self.scroll_to("$scroll_bar", direction="down", steps=5, wait_type="visible")
```

`direction`只接受`"up"`、`"down"`、`"left"`或`"right"`；`steps`必须是非布尔正整数。非法参数立即抛出
`ValueError`，不会静默转换方向或步数。

## 推荐组合

以下是带前提的操作组合，不是所有控件的统一流程。命名 locator 和 data 必须已在
所属资源中声明；按本次目标选择必要等待、读取和独立断言，不照搬示例常量作为业务预期。

### 等待后点击

当“按钮已启用”确为动作前提时，检查等待返回值后点击。该组合不证明点击后的业务
已经完成，保存结果等仍需另行观察。

```python
if not self.wait_enabled("$loc:save_button", timeout=10):
  raise TimeoutError("保存按钮未启用")
self.click("$loc:save_button")
```

### 输入后断言

输入引用静态 data 后读取字段 Value。该组合验证当前控件值；产品需要提交或异步更新
时，应在适当阶段再读，不能把未提交的显示值当成最终业务值。

```python
self.input_text("$name_input", "$customer_name", use_paste=True)
self.assert_attr_contains("$name_input", "value", "$customer_name")
```

### 图片定位限定 Region

前提是存在 `Bdd/data/111.png` 且 `notepad_window` 是正确区域。结果仍是布尔等待，
不是报告通过；正式复用时优先将模板和区域一起放入命名图片 locator。

```python
self.wait_pic_present("111", region="$notepad_window", timeout=10)
```

### OCR 相对点击

前提是 `customer_form` 已作为所属窗口包内的结构区域声明，且锚点文字与当前界面一致。
先检查文字等待结果再相对点击，不因先调用了等待就忽略 `False`。

```yaml
name_label:
  by: ocr
  value: 姓名
  region: customer_form
```

```python
if not self.wait_ocr_text_present("姓名", region="$customer_form", timeout=10):
  raise TimeoutError("姓名锚点未出现")
self.click_ocr_relative("$name_label", direction="right", offset=20)
```

动作层和 Page Object 的维护边界见 [维护/2.架构设计](维护/2.架构设计.md) 与
[2.编写自动化脚本](2.编写自动化脚本.md)。
