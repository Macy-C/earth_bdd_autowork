# 3. 动作参考

本文档记录框架可通过 WindowPage/WindowView 调用的通用动作。README 只保留框架规则和工程标准，具体动作 API 统一放在这里维护。

## 调用入口

业务窗口页面继承 `WindowPage`，测试代码通过其继承的 `BasePage` 方法调用动作：

```python
from autowork_core.page import WindowPage


class CustomerPage(WindowPage):
    root_locator_file = "customer/window.yaml"
    root_locator = "customer_window"
    data_file = "customer_data.yaml"

    def search_customer(self, customer_name):
        self.input_text("$customer_search_input", customer_name)
        self.click("$search_button")
        self.wait_visible("$customer_list")
```

底层函数位于 `autowork_core/actions/`，Step 不直接导入这些函数。Step 可以通过
`get_page()` 获得的 WindowPage/WindowView 调用 BasePage API，实现首次出现或场景特有
的线性流程；locator 必须是所属窗口包中的严格引用。稳定复用流程才提取为页面业务方法。

维护者新增公开 `BasePage` 方法时，必须同时在 `AI_CAPABILITIES` 中显式分类。只有
`plan_enabled=True` 的动作会成为AI Plan operation；`plan_enabled=False` 只允许AI在Page
实现中作为辅助API调用，仅调试和策略禁止接口不向生成开放。所有类别都必须登记，
Generation Contract会拒绝任何未分类或已失效的公开方法。

## 参数约定

| 参数 | 说明 |
| --- | --- |
| `locator_or_name` | `$name` / `$loc:name` 表示 locator 引用；不带 `$` 的字符串按 legacy 临时结构 locator 处理；也可传 dict locator |
| `data_or_name` | `$name` / `$data:name` 表示 data 引用；不带 `$` 的字符串按直接文本处理 |
| `text` / `expected` | OCR 文本或断言期望文本；引用资源时使用 `$loc:name` / `$data:name` |
| `region` | 限定视觉识别区域，可传 `$locator`、locator dict、矩形 dict 或 `(left, top, width, height)` |
| `wait_type` | UIA 目标等待条件，可选 `None`/`none`、`exists`、`visible`、`enabled`、`ready` |
| `wait_timeout` | Child/XPath 目标出现并达到等待条件的总上限，单位秒 |
| `visual_timeout` | OCR/PIC/坐标等视觉定位等待上限，单位秒 |
| `timeout` | 显式 wait、断言、OCR/PIC 动作的等待上限，单位秒 |
| `interval` | 轮询间隔，单位秒 |
| `msg` | 自定义断言失败信息 |
| `variable_name` | 当前 Scenario 内的 ASCII 变量名，必须匹配 `[A-Za-z_][A-Za-z0-9_]{0,63}` |
| `overwrite` | 是否允许覆盖当前 Scenario 中已存在的同名变量，默认 `False` |
| `allow_empty` | 是否允许保存 `None` 或空字符串，默认 `False` |

资源引用必须显式使用 `$`。不带 `$` 的字符串不会自动查 locator/data，而是按临时 locator 或直接文本处理：

| 写法 | 含义 |
| --- | --- |
| `$save_button` | 在 locator 参数中严格引用 locator；在 data 参数中严格引用 data；在 OCR 文本中自动查 locator/data |
| `$loc:save_button` | 强制严格引用 locator |
| `$data:customer_name` | 强制严格引用 data |
| `$$100` | 字面量 `$100` |

严格引用找不到 key 会立即报错；`$name` 在 OCR 文本中同时命中 locator 和 data 时会报歧义，请改用 `$loc:name` 或 `$data:name`。

无前缀临时 locator 只按 `auto_id`、Accessible Name 依次做精确结构查询，并记录
legacy迁移警告；结构查询失败会直接报错，不再隐式切换到OCR。视觉定位必须显式使用
OCR/PIC locator并限定`region`。

## Scenario 变量

Scenario 变量用于把运行时读取结果显式传给当前 Scenario 的后续 Step。变量保存在
`context.autowork_scenario.variables`，不写入静态 YAML data，也不会跨 Scenario 保留。
任意 Page/View 实例都访问当前 Scenario 的同一变量集合：

```python
@when("记录当前订单编号")
def step_impl(context):
  page = get_page(context, OrderPage)
  page.save_text("$order_id", "order_id")


@then("可以按该订单编号查询")
def step_impl(context):
  page = get_page(context, SearchPage)
  page.input_text("$search_input", page.get_variable("order_id"))
```

`save_text()`复用`get_text()`的控件值和可访问文本读取规则；`save_attr()`复用
`get_attr()`，不另建控件读取规则。`0`和`False`会原样保存，只有`None`和空字符串
默认视为空值。重复变量名默认失败，确需更新时显式传`overwrite=True`；确需保存空值
时显式传`allow_empty=True`。

Scenario变量没有`$variable`引用语法；`$name`和`$data:name`仍只表示静态data。
变量API的调用日志只记录变量名和策略，不记录保存值。`save_text()`和`save_attr()`可由
Recorder Plan 4.1在F9 Observation证据支持时生产`result_binding`；后续operation通过
`source=runtime.<binding>`消费。`get_variable()`只作为生成代码的实现辅助，
`set_variable()`不向Recorder Plan开放。框架校验同Scenario内唯一、先生产后消费、至少
一个consumer及Plan-to-Code调用闭包，但不会按值相同或Step相邻自动建立业务关系。

## 定位等待策略

框架现在把 UIA 等待和视觉等待拆开，避免所有动作都走较重的 `ready` 判断。

| 参数 | 控制范围 | 说明 |
| --- | --- | --- |
| `wait_type` | UIA 目标条件 | `exists` 等目标出现，`visible` 等出现且可见，`enabled` 等出现且可用，`ready` 等出现、可见且可用；`None`/`none`/`off`/`0` 只探测一次 |
| `wait_timeout` | UIA 目标等待 | 控制 Child/XPath 目标出现并达到 `wait_type` 的总等待上限，不影响 OCR/PIC 轮询 |
| `visual_timeout` | 视觉定位等待 | 主要影响 OCR/PIC/坐标等视觉定位；普通 UIA child/xpath 通常不用改 |
| `timeout` / `interval` | 显式 wait、断言、视觉动作 | `wait_exists()`、`assert_exists()`、`wait_pic_present()` 等使用这个旧口径 |

默认策略：

| 动作 | 默认等待 | 原因 |
| --- | --- | --- |
| `click()` / `double_click()` / `right_click()` / `focus()` | `wait_type="visible"` | 点击类动作只需要目标可见；`Thumb`、`Text`、`Custom` 等控件经常不适合强制 `enabled` |
| `input_text()` / `send_text_keys()` / `clear_text()` | `wait_type="enabled"` | 输入类动作通常需要控件可编辑或可接收键盘 |
| `wait_ready()` | 显式 `ready` | 只在确实需要“可见且可用”的同步点使用 |
| OCR/PIC 动作 | `timeout` / `interval` | 视觉识别有独立轮询，不使用 `wait_type` |

常见选择：

```python
self.click("$save_button")                         # 默认 visible，速度更稳
self.click("$submit_button", wait_type="enabled") # 点击前必须等按钮解禁
self.wait_ready("$main_window", timeout=15)        # 明确需要 ready 时显式等待
self.click("$static_text", wait_type="exists")     # Text 控件只要求存在
```

## `root` 和 `region` 的选择

`root` 只引用顶层窗口，用于 Child/XPath 元素定位。`region` 引用普通 Child/XPath locator，只影响 OCR/PIC 的截图范围。

推荐顺序：

| 场景 | 推荐写法 |
| --- | --- |
| 长期维护的图片/OCR locator | 在 locator 中写 `region` |
| 临时调试、临时缩小截图范围 | 调用动作时传 `region` |
| 同一个模板偶尔要在不同区域找 | 模板条件保持不变，每次传不同 `region` |

如果 OCR/PIC locator 自带 YAML `region`，动作调用时又传了 `region`，则动作参数优先，只覆盖本次截图范围。
Region 复用普通 Child/XPath locator 的查询结果；匹配多个元素时会记录 ERROR 日志并使用第一个候选，不抛出歧义异常。

```python
# 默认使用 save_icon locator 中配置的 region
self.wait_pic_present("$save_icon")

# 本次调用临时改为只在 dialog_window 区域搜索
self.wait_pic_present("$save_icon", region="$dialog_window")
```

## 点击和焦点

### `click(locator_or_name, wait_type="visible", wait_timeout=5, visual_timeout=10)`

单击目标。目标可以是普通 UIA 控件，也可以是 OCR、图片或坐标 locator 返回的点。
默认只等待目标可见，避免对 `Text`、`Thumb`、`Custom` 等控件误用 `ready` 或 `enabled` 导致慢和误失败。
Child/XPath 目标尚未进入 UIA 树时，`click()` 会在 `wait_timeout` 内重新查询；不需要先调用一次 `wait_visible()`。

```python
self.click("$save_button")
self.click("$submit_button", wait_type="enabled", wait_timeout=10)
self.click({"root": "main_window", "by": "xpath", "value": "//Button[@name='保存']"})
self.click("$save_by_ocr")
```

### `double_click(locator_or_name, wait_type="visible", wait_timeout=5, visual_timeout=10)`

双击目标。

```python
self.double_click("$customer_row")
```

### `right_click(locator_or_name, wait_type="visible", wait_timeout=5, visual_timeout=10)`

右键点击目标。

```python
self.right_click("$customer_row")
self.click("$delete_menu_item")  # 菜单项由 click 自身等待出现并可见
```

### `focus(locator_or_name, wait_type="visible", wait_timeout=5, visual_timeout=10)`

让目标获取焦点。坐标型目标会先点击目标点；普通控件优先调用 `set_focus()`，失败时退回点击。

```python
self.focus("$name_input")
```

### `bring_to_front(locator_or_name, wait_type="exists", wait_timeout=5, visual_timeout=10)`

将目标窗口或控件前置并聚焦。普通目标会先尝试从最小化状态恢复，再调用 `set_focus()`；失败时退回 `click_input()`。坐标型目标会点击坐标点。
这个动作不会把窗口设置为 always-on-top，只用于测试步骤中显式激活目标窗口。

```python
self.bring_to_front("$main_window")
self.bring_to_front("$customer_search_input", wait_type="visible")
```

## 输入和键盘

### `input_text(locator_or_name, data_or_name, use_paste=False, wait_type="enabled", wait_timeout=5, visual_timeout=10)`

输入文本。默认会清空原内容。
输入类动作默认等待目标可用；如果目标是坐标、OCR/PIC 或特殊控件，可按实际情况改成 `visible`、`exists` 或 `None`。

```python
self.input_text("$name_input", "$customer_name")
self.input_text("$remark_input", "hello world")
self.input_text("$long_text_input", "$long_text", use_paste=True)
self.input_text("$custom_editor", "text", wait_type="visible")
```

执行策略：

| 目标类型 | 策略 |
| --- | --- |
| 坐标型目标 | 点击坐标，`Ctrl+A` 清空，再发送键盘或粘贴 |
| 标准 Edit 控件 | 优先 `set_edit_text()` |
| 其他控件 | 点击后 `type_keys()`，失败后退回全局 `SendKeys` |

`use_paste=True` 适合长文本、特殊字符或中文输入更稳定的场景。

### `clear_text(locator_or_name, wait_type="enabled", wait_timeout=5, visual_timeout=10)`

清空输入框。

```python
self.clear_text("$name_input")
```

### `send_text_keys(locator_or_name, data_or_name, wait_type="enabled", wait_timeout=5, visual_timeout=10)`

聚焦目标后发送按键字符串，适合 `{ENTER}`、`^a`、快捷键等。

```python
self.send_text_keys("$name_input", "{ENTER}")
self.send_text_keys("$name_input", "^a{BACKSPACE}")
```

## 有状态控件

有状态控件通常优先使用“设置最终状态”的语义动作，而不是重复`click()`。AI可结合
业务意图和Action Knowledge选择其他注册动作；这些API运行时仍要求相应UIA Pattern，
Pattern缺失、控件类型不匹配或最终状态未达到都会失败。

```python
self.set_checked("$enabled_checkbox", True)
self.select_radio("$absolute_mode_radio")
self.select_tab("$advanced_tab")
self.select_list_item("$patient_a_item")
self.select_tree_item("$advanced_node")
self.set_tree_expanded("$advanced_node", True)
self.set_slider_value(
  "$dose_slider",
  50,
  expected_minimum=0,
  expected_maximum=100,
)
```

`select_tab`、`select_list_item`和`select_tree_item`的locator指向录屏实际操作的
`TabItem`、`ListItem/DataItem`或`TreeItem`，不是父容器。这样Plan target仍由同一个
Action指纹授权。CheckBox处于indeterminate状态时`set_checked`会失败，不猜测循环toggle；
Tree展开/收起使用`set_tree_expanded`，与`select_tree_item`分开；Slider值必须在控件
RangeValue允许范围内，AI生成代码还会核对录制时冻结的最小值和最大值。

## 等待

### `wait_exists(locator_or_name, timeout=10, interval=0.5)`

等待元素存在于 UI 树中。

```python
self.wait_exists("$dialog_window", timeout=10)
```

### `wait_visible(locator_or_name, timeout=10, interval=0.5)`

等待元素可见。

```python
self.wait_visible("$success_message", timeout=10)
```

### `wait_enabled(locator_or_name, timeout=10, interval=0.5)`

等待元素可用。

```python
self.wait_enabled("$submit_button", timeout=10)
```

### `wait_ready(locator_or_name, timeout=10, interval=0.5)`

等待元素可见且可用。`ready` 比 `exists`、`visible` 更严格，也更容易在复杂 UIA 控件上变慢；只在真正需要可交互状态时使用。

```python
self.wait_ready("$submit_button", timeout=10)
```

### `wait_exposed(locator_or_name, timeout=10, interval=0.5)`

等待元素可见且可用，并通过元素中心点的 UIA 屏幕命中父链确认目标当前实际暴露。
适合启动加载页或临时窗口可能覆盖旧页面，但旧页面控件仍留在 UIA 树并继续报告
`visible/enabled` 的同步点。无法取得目标矩形、屏幕命中元素或可靠身份时返回 `False`。

```python
self.wait_exposed("$main_page_button", timeout=10)
```

等待状态建议：

| 状态 | 适合场景 |
| --- | --- |
| `exists` | 窗口、弹窗、后台控件创建 |
| `visible` | 提示文本、结果展示、列表加载完成 |
| `enabled` | 按钮解禁、输入框可编辑 |
| `ready` | 确认控件既可见又可用，再执行强交互 |
| `exposed` | 页面切换期间确认控件既 ready，中心点也未被其他窗口覆盖 |

## 读取信息

### `get_text(locator_or_name)`

读取元素文本。内部依次尝试 `window_text()`、`texts()`、`get_value()`、Legacy Value、`element_info.name`。

```python
actual = self.get_text("$result_label")
```

坐标型目标不支持读取文本。

### `get_attr(locator_or_name, attr_name, timeout=3, default=None)`

读取元素属性。

```python

enabled = self.get_attr("$save_button", "enabled", default=False)

```

常用属性：

| 属性 | 说明 |
| --- | --- |
| `name` / `title` / `text` | 控件名称或文本 |
| `value` | 输入框值或 ValuePattern 值 |
| `class_name` | 控件 class name |
| `control_type` | UIA 控件类型 |
| `automation_id` / `auto_id` | AutomationId |
| `enabled` | 是否可用 |
| `visible` | 是否可见 |
| `handle` | 句柄 |
| `coords` | 坐标型目标返回坐标 |

### `get_collection_items(locator_or_name, timeout=5, max_items=200)`

按UI树直接子项顺序读取集合文本，排除ScrollBar chrome。目标必须是结构化UI元素，
`max_items`必须是非布尔正整数；子项数量超过上限时失败，不返回截断结果。

```python
items = self.get_collection_items("$phase_list")
```

## 普通断言

### 存在和状态断言

```python
self.assert_exists("$save_button", timeout=5)
self.assert_not_exists("$loading_mask", timeout=2)
self.assert_visible("$success_message", timeout=5)
self.assert_not_visible("$loading_mask", timeout=2)
self.assert_enabled("$submit_button", timeout=5)
self.assert_disabled("$submit_button", timeout=5)
```

| 方法 | 判断 |
| --- | --- |
| `assert_exists` | 元素应存在 |
| `assert_not_exists` | 元素不应存在 |
| `assert_visible` | 元素应可见 |
| `assert_not_visible` | 元素不应可见 |
| `assert_enabled` | 元素应可用 |
| `assert_disabled` | 元素应不可用 |

### 文本断言

```python
self.assert_text_equal("$result_label", "$expected_result")
self.assert_text_contains("$message_label", "保存成功")
self.assert_text_not_contains("$message_label", "Error")
self.assert_text_empty("$remark_input")
```

`expected` 不带 `$` 时按直接文本处理；需要引用 data 时使用 `$expected_result` 或 `$data:expected_result`。

### 属性断言

```python
self.assert_attr_equal("$save_button", "enabled", True)
self.assert_attr_contains("$name_input", "value", "张三")
```

属性断言适合文本不稳定但 UIA 属性可靠的控件。

### 集合断言

```python
self.assert_collection_equal(
  "$phase_list",
  ["Phase 250 ms", "Phase 350 ms"],
  max_items=200,
)
```

`expected`必须解析为`list`或`tuple`。断言按顺序精确比较，不排序、不忽略重复项；读取目标
不是结构化元素或超过`max_items`时失败关闭。

## OCR 视觉动作

OCR 底层能力在 `autowork_core/common/ocr_engine.py`，动作层在 `autowork_core/actions/visual_actions.py`。

视觉参数优先级统一为：调用时显式参数 > locator 中的覆盖参数 > `config/config.yaml` 默认参数 > `MODE` 预设默认值。OCR 模型仍然只初始化一次；动态覆盖的是每次 `predict()` 调用的检测参数。

OCR locator 可以只写目标文本；需要限定窗口或区域时，通过普通 Child/XPath locator
声明 `region`：

```yaml
main_content:
  root: main_window
  by: xpath
  value: "//Pane[@auto_id='MainContent']"

save_by_ocr:
  by: ocr
  value: Save
  region: main_content
```

也可以对单个 locator 覆盖适合动态调整的参数：

```yaml
small_save_by_ocr:
  by: ocr
  value: Save
  region: main_content
  match_mode: exact
  index: 0
  det_unclip_ratio: 1.8
  det_box_thresh: 0.65
```

| 参数 | 适合位置 | 作用 |
| --- | --- | --- |
| `match_mode` | locator/action | `smart` 先精确再包含，`contains` 包含匹配，`exact` 精确匹配 |
| `index` / `found_index` | locator/action | 多个命中候选时选择第几个 |
| `det_unclip_ratio` | locator | 检测框外扩比例；文字被裁掉时调大，文字粘连时调小 |
| `det_box_thresh` | locator | 检测框阈值；降低可减少漏检，升高可减少误检 |
| `det_limit_side_len` | 少量 locator | 检测输入尺寸；越大越可能识别小字，但更慢 |
| `cache_ttl` / `use_cache` | action/少量 locator | 短时复用 OCR 结果；静态页面更快，动态页面谨慎使用 |
| `timeout` / `interval` | action/locator | 等待上限和轮询间隔；未写时走 `OCR_SETTING` |

`mode`、`warmup`、`recognition_batch_size` 属于全局运行或初始化策略，不建议写进 locator。

### `wait_ocr_text_present(text, timeout=None, interval=None, region=None)`

等待屏幕区域内出现指定文字。

```python

```

### `wait_ocr_text_absent(text, timeout=None, interval=None, region=None)`

等待指定文字消失。

```python

```

### `assert_ocr_contains(text, timeout=None, region=None, msg=None)`

断言 OCR 文本存在。

```python

```

### `assert_ocr_not_contains(text, timeout=None, region=None, msg=None)`

断言 OCR 文本不存在。


## 图片视觉动作

图片识别底层能力在 `autowork_core/common/pic_engine.py`。模板默认从 `Bdd/data/` 读取，不写扩展名时自动补 `.png`。

### 图片条件写法

推荐 locator dict：

```yaml
save_icon:
  by: pic
  file: save_button.png
  region: main_content
  pos: 5
  threshold: 0.75
  method: mstpl
  rgb: true
```

也可以在代码中直接传 dict：

```python
self.assert_pic_exists({
    "file": "save_button.png",
    "threshold": 0.75,
    "method": "mstpl",
    "pos": 5,
})
```

参数默认值：

| 参数 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `file` / `value` | 是 | 无 | 模板文件名或绝对路径 |
| `region` | 否 | 全屏 | 普通 Child/XPath locator 或矩形区域；强烈建议配置 |
| `pos` | 否 | `PIC_SETTING.POS` | 返回模板上的目标点，`5` 为中心 |
| `threshold` / `confidence` | 否 | `PIC_SETTING.THRESHOLD` | 匹配阈值，越高越严格 |
| `method` | 否 | `PIC_SETTING.METHOD` | 可选 `mstpl`、`tpl`、`gmstpl`、`sift`、`brisk`、`akaze`、`orb`、`kaze`、`surf`、`brief`；空值使用 Airtest 默认策略 |
| `rgb` | 否 | `PIC_SETTING.RGB` | 是否启用颜色匹配 |
| `index` / `found_index` | 否 | 不传 | 显式传入时启用多候选选择，按屏幕从上到下、从左到右排序；不传时保持最佳命中快路径 |
| `timeout` | 否 | `PIC_SETTING.TIMEOUT` | 当前图片等待上限 |
| `interval` | 否 | `PIC_SETTING.INTERVAL` | 轮询间隔，越小越灵敏但 CPU 占用更高 |
| `debug_on_fail` | 否 | `PIC_SETTING.DEBUG_ON_FAIL` | 失败时是否保存图片调试图 |
| `scale_max` / `scale_step` | 否 | `PIC_SETTING` | 多尺度匹配参数，主要影响 `mstpl/gmstpl` 的速度和容错 |

图片 `index` 只在显式写入时启用多候选路径，未写 `index` / `found_index` 的图片定位速度和原逻辑一致。多候选能力依赖 Airtest 当前匹配方法，推荐优先配合 `method: tpl` 和较小 `root` / `region` 使用。

### `wait_pic_present(pic_or_name, timeout=None, interval=None, region=None)`

等待图片出现。


### `assert_pic_not_exists(pic_or_name, timeout=None, region=None, msg=None)`

## 窗口、拖拽和滚动

### `set_root(root, name=None)`

临时调试时显式设置当前顶层窗口。长期脚本应在 locator YAML 中声明 Root，并通过
WindowPage 使用；不要依赖运行时 `set_root()` 建立正式页面所有权。

```python
self.set_root({"class_name": "Notepad"}, name="Notepad_window")
```

### `drag_by_offset(target, delta_x, delta_y, wait_type="enabled", wait_timeout=5, visual_timeout=10)`

从结构化源元素中心拖到相对位移。`delta_x`和`delta_y`必须是非布尔整数，且不能同时为0；
坐标/OCR/PIC点不能充当拖拽源。返回目标坐标`(x, y)`。

```python
self.drag_by_offset("$phase_item", delta_x=390, delta_y=1)
```

### `scroll_to(target=None, direction="down", steps=1, wait_type="visible", wait_timeout=5, visual_timeout=10)`

垂直方向发送鼠标滚轮事件。水平滚动必须传入水平`ScrollBar`或其`Thumb`，且控件
必须公开可写的RangeValue Pattern；框架按`SmallChange * steps`计算目标值并在范围内
截断，设置后回读验证。目标类型、方向或RangeValue不满足契约时立即失败，不降级为
方向按钮、Win32消息或水平滚轮。
传目标时默认只等目标可见，避免滚动条 `Thumb` 等控件因为 `enabled` 状态不稳定而误失败。

```python
self.scroll_to(direction="down", steps=3)
self.scroll_to("$customer_list", direction="up", steps=2)
self.scroll_to("$horizontal_scrollbar", direction="right", steps=3)
self.scroll_to("$horizontal_scrollbar", direction="left", steps=2)
self.scroll_to("$scroll_bar", direction="down", steps=5, wait_type="visible")
```

`direction`只接受`"up"`、`"down"`、`"left"`或`"right"`；`steps`必须是非布尔正整数。非法参数立即抛出
`ValueError`，不会静默转换方向或步数。
