# 6. 版本与升级说明

本文记录BDD Autowork框架发布版本及升级影响。内部Evidence、Plan、Transaction、
Run Result等协议各自独立演进，其协议版本不等于框架发布版本。

## 当前版本

| 项目 | 值 |
| --- | --- |
| 最新版本 | `1.1.0` |
| 发布日期 | 2026-08-25 |
| 状态 | 向后兼容功能更新 |

框架发布版本使用`MAJOR.MINOR.PATCH`：不兼容的公开契约变化升级`MAJOR`，向后兼容的
功能升级`MINOR`，向后兼容的缺陷修复升级`PATCH`。正式发布提交应创建同版本
`vMAJOR.MINOR.PATCH` Git标签；协议版本继续由各自代码和设计文档管理。

本文滚动保留最新三个版本条目。由于`1.0.0`之前没有正式Git标签，历史开发里程碑明确
记为开发里程碑，不追溯伪造发布版本，也不能作为受支持的降级目标。

## 1.1.0 - 2026-08-25

向后兼容功能更新，重点改善大量场景报告查看和最终交付报告合并流程。

### 主要变化

- Spark测试详情页优化大量Scenario/Example浏览：压缩左侧导航行，保留列表滚动位置，
  切换场景时右侧详情回到顶部，并提供上一条、下一条和下个需跟进的连续浏览按钮。
- 窄屏详情页标题栏改为可换行布局，Scenario列表继续以抽屉方式展开，避免导航和状态
  控件在移动宽度下互相挤压。
- 新增最终交付报告合并能力。核心实现位于
  `autowork_core.runtime.reporting.final_report`，支持基于普通Spark JSON创建最终报告、
  合并复跑结果、删除误合并结果以及重新渲染最终HTML。
- 宿主侧新增轻量入口`Bdd/final_report.py`。右键运行时只需选择`ACTION`，并只填写对应的
  `CREATE`、`MERGE`、`DELETE`或`RENDER`配置块；最终HTML不显示“复跑后通过”、flaky或
  尝试次数。
- 最终报告输出到`artifacts/final-reports/`，其中`autowork-final-report.json/html`为交付
  报告正文，`autowork-final-merge.json`只保存内部操作日志。合并时会把截图、录屏和调试
  附件快照到`artifacts/final-reports/assets/`，避免普通运行清理`reports/screenshots/recordings`
  后最终报告断链。
- 单次Spark报告仍输出到`artifacts/reports/autowork-report.html/json`并可在下一次运行前
  被清理；不可变Run Result快照仍保留在`artifacts/run-results/`。

### 升级操作

1. 按当前发布源同步规则更新框架拥有目录：`autowork_core/`、顶层`config/`、顶层`ai/`、
  `docs/`、`.github/`、通用`resources/`以及根目录框架文件。
2. 不覆盖宿主业务`Bdd/`目录。若需要右键运行最终报告合并入口，可将发布源中的中性
   `Bdd/final_report.py`复制到宿主项目，或继续使用核心命令行入口：

   ```powershell
   python -m autowork_core.runtime.reporting.final_report --help
   ```

3. 全量运行后创建最终报告底稿；失败Feature或Scenario复跑后，再把复跑生成的普通报告
   合并进最终报告。`Bdd/final_report.py`配置示例：

   ```python
   ACTION = "create"  # create / merge / delete / render

   CREATE = {
       "report_json": "artifacts/reports/autowork-report.json",
   }

   MERGE = {
       "report_json": "artifacts/reports/autowork-report.json",
       "allow_add": False,
       # 目标不唯一时再填写：
       # "feature_file": "Bdd/test_features/login.feature",
       # "scenario_name": "登录成功",
       # "example_id": "1.1",
   }

   DELETE = {
       # 默认从 artifacts/final-reports/autowork-final-report.json 删除。
       # 删除整个 Feature 时填 feature_file 或 feature_name。
       # 删除单个 Scenario/Example 时再填 scenario_name / example_id。
       # "feature_file": "Bdd/test_features/login.feature",
       # "scenario_name": "误合并的场景",
   }

   RENDER = {
       # 默认渲染 artifacts/final-reports/autowork-final-report.json。
   }
   ```

4. 升级后在宿主根目录运行：

   ```powershell
   python -B -m autowork_core.utils.debug_tools.framework_smoke --project-root .
   ```

  只有宿主自己的`Bdd/`也发生变化时，才继续运行对应项目测试。顶层`config/`是框架
  Python包；项目运行配置固定为`Bdd/config.yaml`。

### 升级影响

- 最终报告合并是新增功能，不改变普通Spark报告路径和清理行为；旧的
  `artifacts/reports/autowork-report.html/json`仍只表示最近一次执行。
- `Bdd/final_report.py`属于宿主便捷入口。宿主已经自定义该文件时，不要直接覆盖；可只
  同步`ACTION`配置块写法，或直接调用核心模块。
- `autowork-final-merge.json`不是交付报告正文，只是内部操作日志。需要给外部查看时使用
  `autowork-final-report.html`。

## 1.0.0 - 2026-08-24

首个正式框架发布源版本，没有可直接升级的上一正式版本。

### 主要变化

- 确立框架发布源与宿主项目边界：`autowork_core/`、顶层`config/`、顶层`ai/`、`docs/`、
  `.github/`和通用`resources/`由框架拥有；`Bdd/`和`artifacts/`由宿主拥有。项目运行配置
  固定为`Bdd/config.yaml`。
- 发布源保留中性`Bdd/`参考骨架；产品进程、Page、locator、data、供应商SDK和设备DLL
  不进入框架资产。
- Recorder生成入口收敛为Generation Profile、admission和内容寻址Generation Job；
  Job继续绑定Design、Plan、Transaction、Run Result和Oracle各自的权威结果。
- Spark支持结构化Run Result 1.3诊断及最终报告合并，失败分类、附件和生成provenance
  保持可追溯。
- `framework_validation/`保留在发布源中用于框架测试和评测，但不复制到宿主项目。

### 升级操作

1. 先备份宿主自己的`Bdd/`和需要保留的`artifacts/`证据。
2. 完整替换`autowork_core/`、顶层`config/`、顶层`ai/`、`docs/`、`.github/`、`resources/`以及根目录
   `requirements.txt`、`behave.ini`、`README.md`、`.gitattributes`和`.gitignore`。
3. 不替换`Bdd/ai/`，不把`framework_validation/`复制到宿主项目。
4. 使用`APP_PATH: runtime`的宿主必须实现`Bdd.application.start_application()`和
   `stop_application()`；中性模板会失败关闭，不会假装已启动应用。
5. 在宿主根目录运行：

   ```powershell
   python -B -m autowork_core.utils.debug_tools.framework_smoke --project-root .
   ```

只有宿主自己的`Bdd/`同时发生变化时，才继续运行对应项目测试。录制证据
跨项目或跨机器迁移应使用Recorder便携包，不把`artifacts/`直接当作框架配置覆盖。

## 2026-08-23开发里程碑（未正式发布）

### 主要变化

- 收紧Root、Child和XPath文本语义，生成代码使用严格`$loc:`引用，隐式OCR回退退出
  当前路径。
- Request采用业务身份并与Framework Contract演进解耦；运行授权由显式Execution
  Profile提供。
- Run Result 1.3加入结构化Runtime Diagnostic，区分未找到、状态超时、视觉未命中和
  backend错误，并绑定当前Transaction代码快照。
- Decision媒体、locator候选和独立Oracle加强内容摘要、路径和运行身份校验。

### 升级影响

- 依赖裸locator名称或隐式OCR的生成代码需要改为显式`$loc:`或声明OCR locator。
- 未绑定当前Request、Plan和Transaction的旧Run Result只能作为历史报告，不能升级
  当前生成质量状态。
