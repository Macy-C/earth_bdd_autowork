# 6. 版本与升级说明

本文记录BDD Autowork框架发布版本及升级影响。内部Evidence、Plan、Transaction、
Run Result等协议各自独立演进，其协议版本不等于框架发布版本。

## 当前版本

| 项目 | 值 |
| --- | --- |
| 最新版本 | `1.0.0` |
| 发布日期 | 2026-08-24 |
| 状态 | 首个正式发布源版本 |

框架发布版本使用`MAJOR.MINOR.PATCH`：不兼容的公开契约变化升级`MAJOR`，向后兼容的
功能升级`MINOR`，向后兼容的缺陷修复升级`PATCH`。正式发布提交应创建同版本
`vMAJOR.MINOR.PATCH` Git标签；协议版本继续由各自代码和设计文档管理。

本文滚动保留最新三个版本条目。由于`1.0.0`之前没有正式Git标签，后两条明确记为
开发里程碑，不追溯伪造发布版本，也不能作为受支持的降级目标。

## 1.0.0 - 2026-08-24

首个正式框架发布源版本，没有可直接升级的上一正式版本。

### 主要变化

- 确立框架发布源与宿主项目边界：`autowork_core/`、顶层`ai/`、`docs/`、`.github/`
  和通用`resources/`由框架拥有；`Bdd/`、`config/`和`artifacts/`由宿主拥有。
- 发布源保留中性`Bdd/`参考骨架；产品进程、Page、locator、data、供应商SDK和设备DLL
  不进入框架资产。
- Recorder生成入口收敛为Generation Profile、admission和内容寻址Generation Job；
  Job继续绑定Design、Plan、Transaction、Run Result和Oracle各自的权威结果。
- Spark支持结构化Run Result 1.3诊断及最终报告合并，失败分类、附件和生成provenance
  保持可追溯。
- `framework_validation/`保留在发布源中用于框架测试和评测，但不复制到宿主项目。

### 升级操作

1. 先备份宿主自己的`Bdd/`、`config/`和需要保留的`artifacts/`证据。
2. 完整替换`autowork_core/`、顶层`ai/`、`docs/`、`.github/`、`resources/`以及根目录
   `requirements.txt`、`behave.ini`、`README.md`、`.gitattributes`和`.gitignore`。
3. 不替换`Bdd/ai/`，不把`framework_validation/`复制到宿主项目。
4. 使用`APP_PATH: runtime`的宿主必须实现`Bdd.application.start_application()`和
   `stop_application()`；中性模板会失败关闭，不会假装已启动应用。
5. 在宿主根目录运行：

   ```powershell
   python -B -m autowork_core.utils.debug_tools.framework_smoke --project-root .
   ```

只有宿主自己的`Bdd/`或`config/`同时发生变化时，才继续运行对应项目测试。录制证据
跨项目或跨机器迁移应使用Recorder便携包，不把`artifacts/`直接当作框架配置覆盖。

## 2026-08-23开发里程碑（未正式发布）

### 主要变化

- 收紧Root、Child和XPath文本语义，生成代码使用严格`$loc:`引用，隐式OCR回退退出
  当前路径。
- Request采用业务身份并与Framework Contract演进解耦；运行授权由显式Execution
  Profile提供。
- Run Result 1.3加入结构化Runtime Diagnostic，区分未找到、状态超时、视觉未命中和
  backend错误，并绑定当前Transaction代码快照。
- Decision媒体、locator候选和独立Oracle加强内容摘要、路径和运行身份校验。

### 升级影响

- 依赖裸locator名称或隐式OCR的生成代码需要改为显式`$loc:`或声明OCR locator。
- 未绑定当前Request、Plan和Transaction的旧Run Result只能作为历史报告，不能升级
  当前生成质量状态。

## 2026-08-21开发里程碑（未正式发布）

### 主要变化

- 生成链收敛为GenerationDesign、确定性Plan、Implementation Manifest和
  GenerationTransaction，分离AI可编辑、系统拥有和只读复用文件。
- locator、PIC和包标记由Transaction在文件租约与可恢复journal内物化。
- 实现验证使用追加式修复ledger；`finish`重验源码快照、scope、Plan-to-Code和lease。

### 升级影响

- AI或人工实现不能写入Manifest未声明的文件，也不能自行物化系统拥有的locator/PIC
  变更。
- 旧Transaction报告与后续源码快照不一致时只能作为历史记录，不能直接作为当前实现的
  完成证明。
