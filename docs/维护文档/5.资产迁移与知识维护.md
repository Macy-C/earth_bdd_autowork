# 5. 资产迁移与知识维护
文档哈希（SHA256）：`72d6b396e9d9c51f121e739559f3fcca33373b0a3c362e963a57e11f8245c053`

本章面向维护者，说明 AI 资产、运行知识采集和跨机器交付的所有权、保留与
恢复规则。它不替代当前代码、测试或冻结运行证据；发生冲突时以它们为准。

## 资产边界

| 位置 | 所有者与用途 | 生命周期 |
| --- | --- | --- |
| `ai/` | 框架的 Context、Prompt、Schema 和 Policy | 随框架版本化，可整体替换 |
| `.github/` | Copilot Skill、Prompt和小型确定性Hook | 随框架版本化，不复制canonical正文 |
| `Bdd/config.yaml` | 项目运行配置与知识库绑定（`WEKNORA_SETTING.KNOWLEDGE_BASES`） | 随宿主项目保留，不被框架同步覆盖 |
| `artifacts/ai/` | 本地维护期 Collaboration Review/Promotion 和 Shadow Companion 状态 | 本地缓存，Git 忽略 |
| `artifacts/knowledge-captures/<run>/` | BDD 运行观察、PNG、润色规格与派生案例 | 保留到该 Run 的每个案例被远端接受且无待退役旧版后，才可整 Run 清理 |
| Copilot memory、聊天和复用索引 | 本机或派生缓存 | 可丢失，不能成为唯一事实源 |

框架更新替换顶层 `ai/` 和对应 `.github/` 发现适配器，保留项目的 `Bdd/` 和 `artifacts/`。
`.github/copilot-instructions.md`、`.github/skills/`、`.github/prompts/`和
`.github/hooks/`位于Copilot固定发现路径；正文规则仍以`ai/`为权威，不能维护两套细则。

## 协作复盘记录

Collaboration Review/Promotion 采用“只读复盘 -> 明确批准 -> 最小晋升”：

- Review/Promotion 只由框架维护者显式调用，不能由 SessionStart、会话数量、时间或项目活动触发。
- Review 只产生候选，保存简短证据摘要和回合引用；不得存完整聊天、私有路径或凭据。
- Promotion 只接受当前请求中明确批准的候选 ID，并只改一处最小持久化目标。
- Review 和 Promotion 回执是本地知识，位于 `artifacts/ai/knowledge/`，受 `.gitignore`（`artifacts/`）保护，默认不进入 Git。

## 跨机器交付与框架升级

更新框架或换机器时：

1. 保留项目的 `Bdd/`（含 `Bdd/config.yaml` 中的运行与知识库配置）。
2. 在新位置恢复仓库，重建 Python、ffmpeg 和 OCR 模型，并配置好 WeKnora 访问凭据。
3. 运行轻量冒烟检查：

```powershell
python -B -m autowork_core.utils.debug_tools.framework_smoke --project-root .
```

## 恢复与按需路由

新会话以 [仓库通用规则](../../.github/copilot-instructions.md)、[架构设计](2.架构设计.md)和当前 Git/code/test/evidence
为准；本章只在资产生命周期、备份、知识维护、交付或同步任务时读取。不要复制 VS Code
`workspaceStorage` 作为长期恢复方案，因为 workspace identity 和内部格式不稳定。

框架架构的临时修复计划应放在关联 Issue 或 PR，而不是 `ai/context`。Issue/PR 关闭后，
保留代码、测试和维护文档中的长期结论，删除临时计划或将其留在远端历史中。
