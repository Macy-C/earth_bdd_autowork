# 4. 定位器与配置

本文是 locator、data、Root 与运行配置的统一参考。先按结构定位规则写脚本，只在需要
改变项目默认行为时查看后半部分配置表。

## Locator 工作台

运行 `python -m Bdd.debug_tools` 会打开唯一的 Locator 工作台。顶部统一选择目标窗口；
左侧控件树和右侧 XPath 检查器共享同一个窗口、选中控件、框选与剪贴板状态。右侧
“验证工具”页按能力分为结构定位（Child、坐标）和视觉定位（OCR、图片），入口仍调用
各工具原有的验证实现，不维护第二套定位规则或状态。Recorder 通过标题栏中的唯一
“Recorder 工作台”入口打开，保持独立的录制任务工作区。

## 目录

| 目录 | 用途 |
| --- | --- |
| `Bdd/locators/` | 页面定位器 YAML |
| `Bdd/data/` | 测试数据 YAML 和图片模板 |
| `Bdd/page_obj/` | 页面对象；WindowPage 声明窗口包，历史 BasePage 声明 locator/data 文件 |

运行级公共资源：

| 文件 | 加载时机 | 说明 |
| --- | --- | --- |
| `Bdd/data/public_data.yaml` | `before_all` | 公共 data，所有页面都可读 |

页面资源：

```python
class CustomerPage(WindowPage):
  root_locator_file = "customer/window.yaml"
  root_locator = "customer_window"
  data_file = "customer_data.yaml"
```

WindowPage 初始化时会原子编译窗口包并加载 data。声明的文件不存在会直接报
`FileNotFoundError`，空 YAML 会当作空字典处理。

桌面长期脚本使用 `WindowPage`/`WindowView`。一个窗口目录可以拆多个子页面文件，
但整个窗口包只能声明一个 top-level Root；完整所有权规则见
[2.编写自动化脚本：窗口与子页面所有权](2.编写自动化脚本.md#窗口与子页面所有权)。

历史 `BasePage` 页面较大时仍可声明多个资源文件：

```python
class OrderFilterPanel(BasePage):
    locator_files = [
        "orders/common.yaml",
        "orders/filter.yaml",
    ]
    data_files = ["order_filter_data.yaml"]
```

`locator_file` / `locator_files` 都是相对 `Bdd/locators/` 的路径；`data_file` / `data_files` 都是相对 `Bdd/data/` 的路径。子目录用 `/` 写即可。加载顺序是先加载列表属性，再加载单文件属性；同名 key 后加载的会覆盖先加载的。因此也可以这样写公共 + 子页面：

```python
class OrderFilterPanel(BasePage):
    locator_files = ["orders/common.yaml"]
    locator_file = "orders/filter.yaml"
    data_file = "order_filter_data.yaml"
```

如果不想为当前 step 额外建页面类，可以使用通用脚本页并在运行时声明资源：

```python
from autowork_core.page import get_script_page


def step_impl(context):
    ui = get_script_page(
        context,
        locator_files=[
            "orders/common.yaml",
            "orders/filter.yaml",
        ],
        data_file="order_filter_data.yaml",
    )
    ui.click("status_filter_dropdown")
    ui.assert_ocr_contains("Active", region="status_filter_options")
```

通用脚本页适合临时动作、一次性断言、录制回放或还没沉淀成 WindowPage 的脚本。
它不能绕过窗口归属不确定性；稳定复用的业务能力应进入 WindowPage/WindowView。

`get_script_page` 会复用同一个 `ScriptPage` 实例，并按调用参数增量加载资源。若要重建实例并重置已加载记录，可传 `refresh=True`。

## 资源作用域

`context.autowork_feature.locators` 和 `context.autowork_feature.data` 都是 `Stratify`
对象。每个 Feature 的 locator 容器从空状态开始，由 Page 或脚本页显式加载；data
容器从 RunState 的公共 data 模板 fork，再加载页面或 Feature data。

data 查找优先级：

```text
当前页面/Feature data > public_data.yaml > None
```

locator 没有公共回退。`WindowPage` 只解析自己的窗口包；历史 `BasePage` 和
`ScriptPage` 只解析显式加载到当前 Feature 的 locator 文件。

`BasePage` 使用显式资源引用。需要引用 locator/data 时加 `$`：

```python
self.click("$save_button")
self.input_text("$name_input", "$customer_name")
```

- `$save_button` 会严格查 `context.autowork_feature.locators`。
- `$customer_name` 会在 data 参数中严格查 `context.autowork_feature.data`。
- 不带 `$` 的字符串不再自动查资源：locator 参数按临时 locator，data 参数按直接文本。

临时调试仍可直接传临时 locator 或直接文本；长期脚本建议把稳定 locator/data 沉淀到 YAML，并用 `$` 引用。

引用规则：

| 写法 | 使用位置 | 行为 |
| --- | --- | --- |
| `$save_button` | locator 参数 | 必须命中 locator `save_button` |
| `$customer_name` | data 参数 | 必须命中 data `customer_name` |
| `$success_message` | OCR 文本参数 | 自动查 locator/data；两边都命中时报歧义 |
| `$loc:success_message` | 任意支持视觉值的位置 | 强制按 locator 解析 |
| `$data:success_message` | 任意支持视觉值的位置 | 强制按 data 解析 |
| `$$100` | 任意字符串参数 | 字面量 `$100` |

## Locator 基本格式

推荐使用 dict 写法：

```yaml
locator_name:
  root: some_root
  by: child | xpath | pos
  value: xxx
```

基本规则：

- `root` 只能引用顶层窗口 locator，用于限定 Child/XPath 查询所属窗口。
- `by` 表示定位方式；不写时默认按 `child` 处理。
- `xpath`、`ocr`、`pic`、`pos` 也推荐使用 dict 写法。
- 旧字符串写法仍兼容，适合临时调试和历史 locator。
- 无前缀字符串是legacy临时locator，只依次精确查询`auto_id`和Accessible Name；不会
  隐式回退OCR。视觉定位必须显式声明`by: ocr`/`by: pic`和`region`。
- Child/XPath 不支持中间 Root；容器关系应直接写进完整 XPath。
- OCR/PIC locator 不支持 `root`，需要缩小截图范围时配置 `region` 或调用时传入 region。

## 顶层窗口

顶层窗口通常不写 `root`。

```yaml
calc_window:
  backend: uia
  control_type: Window
  title_re: "计算器"
```

如果窗口标题不稳定，优先使用 `class_name`、`auto_id`、`title_re` 等组合条件。

```yaml
customer_window:
  backend: uia
  control_type: Window
  auto_id: "CustomerForm"
```

## Child 定位

```yaml
equal_button:
  root: calc_window
  by: child
  control_type: Button
  auto_id: "equalButton"
```

`by: child` 可省略：

```yaml
equal_button:
  root: calc_window
  control_type: Button
  auto_id: "equalButton"
```

常用字段别名：

| 目标 | 支持写法 |
| --- | --- |
| 文本 | `name`、`text`、`title`、`caption`、`label` |
| AutomationId | `auto_id`、`automation_id`、`id` |
| 控件类型 | `control_type`、`type`、`tag`、`role` |
| 类名 | `class_name`、`class`、`classname` |

结构定位中的`name`统一表示控件的Accessible Name。`text`、`title`、`caption`和
`label`只是历史输入别名，也按同一个Accessible Name精确比较，不表示Edit/Document
正文；`title_re`等正则同样只匹配Accessible Name。Accessible Name为空时保持为空，
属性读取失败会作为backend错误暴露，不会改读`window_text`、`rich_text`或OCR。

Child locator 不接受 `index` / `found_index`。`first_only` 属于调用方式，不属于 locator 条件：

- `first_only=True`：按 Child 条件定位单个目标；匹配多个时按单元素语义报歧义，不会静默取第一个。
- `first_only=False`：使用框架兼容分支返回全部匹配元素列表。

Child 验证器固定执行唯一性校验：先通过 `first_only=False` 统计全部候选；只有数量恰好为 `1`，并且该元素满足等待状态时才验证通过。`0` 个表示未找到，多个表示 locator 不唯一，调试器会框选并列出全部候选。需要按第 N 个目标定位时，应改用 XPath `[N]`，例如 `//Button[@name='Save'][1]`。

调试工具的 Child“超时秒”表示轮询等待上限。验证器每隔约 `0.2` 秒按当前条件重新查询，并检查所选等待状态（`exists`、`visible`、`enabled`、`ready` 或 `none`）；填写 `0` 时只查询一次。

Child 验证器直接提供 `control_type`、`auto_id`、`title` 和 `class_name`。其他核心过滤条件通过“其他条件（YAML）”填写，支持：

```yaml
title_re: "^Save"
auto_id_re: "^save"
class_name_re: "Button$"
process: 1234
handle: 5678
depth: 2
framework_id: Win32
visible: true
enabled: true
```

可用键由框架核心 `CHILD_FILTER_KEYS` 统一定义；验证器不会维护另一份定位规则。Root 和 backend 由调试器窗口选择负责，不放入“其他条件”。

示例：

```yaml
guest_button:
  root: customer_window
  control_type: Button
  auto_id: "GuestButton"
```

## XPath 定位

推荐 dict 写法：

```yaml
num1_button:
  root: calc_window
  by: xpath
  value: "//Button[@auto_id='num1Button']"
```

旧字符串兼容：

```yaml
num1_button_old: root = calc_window | //Button[@auto_id='num1Button']
```

兄弟级定位：

```yaml
name_input:
  root: customer_window
  by: xpath
  value: "//Text[@name='Name']/next::Edit"

query_prev:
  root: customer_window
  by: xpath
  value: "//Button[@name='Search']/prev::*[0]"
```

规则：

- `next::` / `following-sibling::` 表示后面的兄弟控件。
- `prev::` / `preceding-sibling::` 表示前面的兄弟控件。
- `prev::*[0]` 是最近的前一个兄弟。
- `prev::*[1]` 是再前一个。
- `next::*[0]` 是最近的后一个兄弟。

父级定位：

```yaml
customer_group:
  root: customer_window
  by: xpath
  value: "//Text[@name='Name']/parent::Group"
```

也支持显式 `child::`、`descendant::` 和 `ancestor::`。例如在稳定导航树分支内定位：

```yaml
license_status:
  root: preferences_window
  by: xpath
  value: "//TreeItem[@name='Settings']/descendant::TreeItem[@name='Licensing']/child::Text[@name='Status']"
```

这是面向 Windows 控件树的受控 XPath 子集，不是完整 W3C XPath。支持 `/` 子级、`//`
后代、上述父级/祖先/兄弟轴、`*`、零基正负索引、属性相等、`and` 和 `contains()`；不支持
联合表达式、任意 XPath 函数或通用布尔/算术表达式。

XPath 属性名尽量贴近 Microsoft Inspect 常见属性，支持 `framework_id`、`help_text`、`value`、`enabled`、`visible`、`offscreen`、`legacy_value` 等过滤。

```yaml
save_button:
  root: customer_window
  by: xpath
  value: "//Button[@name='Save' and @enabled='true']"

name_edit:
  root: customer_window
  by: xpath
  value: "//Edit[@value='Example Customer']"
```

## OCR 定位

```yaml
save_by_ocr:
  by: ocr
  value: Save
  region: save_panel
```

需要特殊调参时，在 locator 中只写覆盖项，未写的继续走 `OCR_SETTING`：

```yaml
small_text_by_ocr:
  by: ocr
  value: Save
  region: save_panel
  match_mode: exact
  index: 0
  det_unclip_ratio: 1.8
  det_box_thresh: 0.65
```

规则：

- OCR locator 应尽量配置 `region`；region 引用一个普通 Child/XPath locator。
- 只在 UIA/child/xpath 不可靠时使用 OCR。
- 文本较短或容易混淆时，优先缩小 region 区域。
- 适合动态覆盖：`match_mode`、`index`、`det_unclip_ratio`、`det_box_thresh`。
- 谨慎动态覆盖：`det_limit_side_len`、`cache_ttl`。
- 不建议 locator 覆盖：`mode`、`warmup`、`recognition_batch_size`。
- 显式 OCR locator 失败会保存 `artifacts/screenshots/ocr_find_failed_*.png`。

## 图片定位

```yaml
save_icon:
  by: pic
  file: save_button.png
  region: toolbar_region
  pos: 5
  threshold: 0.75
  method: mstpl
  rgb: true
```

图片模板默认从 `Bdd/data/` 目录读取，不写扩展名时默认补 `.png`。

| 字段 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `file` / `value` | 是 | 无 | 模板文件名或绝对路径 |
| `region` | 否 | 全屏 | 普通 Child/XPath locator 名称，用其矩形限定搜索区域 |
| `pos` | 否 | `PIC_SETTING.POS` | 返回模板上的目标点，`5` 为中心 |
| `threshold` / `confidence` | 否 | `PIC_SETTING.THRESHOLD` | 匹配阈值，越高越严格 |
| `method` | 否 | `PIC_SETTING.METHOD` | 如 `mstpl`、`tpl`、`sift`、`brisk`；空值使用 Airtest 默认策略 |
| `rgb` | 否 | `PIC_SETTING.RGB` | 是否启用颜色匹配 |
| `index` / `found_index` | 否 | 不传 | 显式传入时启用多候选选择，按屏幕从上到下、从左到右排序；不传时保持最佳命中快路径 |
| `timeout` | 否 | `PIC_SETTING.TIMEOUT` | 当前图片等待上限 |
| `interval` | 否 | `PIC_SETTING.INTERVAL` | 轮询间隔，越小越灵敏但 CPU 占用更高 |
| `scale_max` / `scale_step` | 否 | `PIC_SETTING` | 多尺度匹配参数，主要影响 `mstpl/gmstpl` 的速度和容错 |

图片 `index` 只在显式写入时启用多候选路径。默认不写时仍走单个最佳命中，不影响原有速度。需要第 N 个相同图标时，建议先缩小 `region`，再设置 `index` 或 `found_index`。

临时字符串：

```python
self.wait_pic_present("root=Notepad_window|111")
self.wait_pic_present("root=Notepad_window|pic=111")
```

显式图片 locator 失败会保存 `artifacts/screenshots/pic_find_failed_*.png`。

## 坐标定位

```yaml
fixed_pos:
  by: pos
  coords: [570, 745, 1920, 1080]
```

字符串写法：

```yaml
fixed_pos_text: "pos:570,745,1920,1080"
```

坐标必须包含 `x, y, source_width, source_height` 四个整数，来源桌面宽高必须大于 0；两值写法会在 locator 编译阶段直接报错。运行时会按配置中的桌面尺寸做比例换算。坐标定位适合调试或无法稳定识别的兜底场景，不建议作为长期主定位方式。

可在 `python -m Bdd.debug_tools` 的“坐标验证”中填写来源桌面尺寸并验证最终换算落点。坐标窗口打开时，将鼠标移动到目标位置后按 `F4`，即可读取当前坐标；窗口未打开时 `F4` 不执行坐标读取。

## RootStore

RootStore 在当前 Scenario 内缓存顶层窗口。普通 Child/XPath locator 直接引用顶层
Root；中间容器通过 locator 表达，不作为第二个窗口 Root。

```yaml
main_window:
  backend: uia
  control_type: Window
  title_re: "业务系统"

customer_panel:
  root: main_window
  control_type: Pane
  auto_id: "CustomerPanel"

search_button:
  root: main_window
  by: xpath
  value: //Pane[@auto_id='CustomerPanel']//Button[@name='Search']
```

长期用例应在 YAML 中声明顶层窗口。仅临时调试时可以显式设置当前窗口：

```python
self.set_root({"class_name": "Notepad"}, name="Notepad_window")
```

Root 缓存只在当前 Scenario 有效。窗口关闭并重开后，框架会检查缓存 handle，并在失效
时按原 locator 重新定位；业务代码不应直接读写 RootStore 或依赖其内部状态。

定位规则：

- locator 中的 `root` 必须引用顶层窗口，并优先命中 `RootStore` 缓存。
- 没有指定 `root` 时，普通定位会回退到 `last_root`。
- 顶层窗口 root 建议写 `control_type: Window` 或显式 `top_level: true`，避免把普通 child 条件误当最终控件定位。
- Child 条件在顶层窗口内不唯一时，应改用完整 XPath 表达祖先关系。
- OCR/PIC 的 `region` 引用普通 Child/XPath locator；显式动作参数 region 优先于 YAML region。
- Region locator 自身可以引用顶层 root，但不能是 OCR/PIC/POS，且必须唯一定位到有有效矩形的元素；匹配多个元素时抛出 `ElementAmbiguousError`，不会静默使用第一个候选。
- 多个 YAML 文件只用于组织，加载后合并到同一 Feature locator 映射，不形成文件级作用域。

窗口与子页面如何划分见
[2.编写自动化脚本：窗口与子页面所有权](2.编写自动化脚本.md#窗口与子页面所有权)。
Root 缓存实现细节见 [维护/2.架构设计](维护/2.架构设计.md#root-缓存)。

## Data 规则

`Bdd/data/*.yaml` 用于维护测试数据或图片模板文件。页面对象通过 `data_file` 或 `data_files` 声明：

```python
class CustomerPage(BasePage):
  data_file = "customer_data.yaml"
```

多个页面共享同一组业务数据时，可以让不同 Page Object 指向同一个 data 文件；需要组合公共数据和业务数据时使用 `data_files`。

示例：

```yaml
customer_name: Example Customer
customer_id: C0001
remark: 自动化测试数据
```

页面中调用：

```python
self.input_text("$customer_name_input", "$customer_name")
self.assert_text_contains("$customer_row", "$customer_name")
```

不带 `$` 的 data 参数会作为直接文本使用：

```python
self.input_text("remark_input", "hello world")
```

如果希望引用 data，并在 key 拼错时立即失败，使用 `$data_key` 或 `$data:data_key`：

```python
self.input_text("customer_name_input", "$customer_name")
self.assert_text_contains("customer_row", "$customer_name")
```

## 命名建议

- locator 名称使用业务含义，如 `customer_search_input`、`save_button`。
- 避免只用控件类型命名，如 `button1`、`edit2`。
- 图片模板文件名和 locator 名称尽量对应，如 `save_icon.png` 对应 `save_icon`。
- data 名称表达数据含义，如 `customer_name`、`invalid_password`。
- 每个顶层窗口的 Root 和控件放入所属 `WindowPage` 窗口包。
- 同一窗口内共享的导航或区域使用 `WindowView`，locator 仍放在该窗口目录。
- 偶现但独立的顶层提示窗口也使用单独的 `WindowPage`，通过 `wait_until_open()`
  判断是否出现。

## 配置模型

运行配置分两层：`config/config.yaml` 保存项目默认值；`settings_overrides` 只覆盖当前
本地运行，结束后自动恢复。配置加载到 `config.settings.settings`。YAML 使用分组字段，
Python 使用扁平属性名，例如 `RECORD_SETTING.MODE` 对应 `settings.record_mode`。

```yaml
log:
  file: "logs.logs"
  level: "INFO"

draw_outline_location: false
APP_LAUNCH_MODE: "auto"

APP_SETTING:
  APP_PATH: "notepad"
  BACKEND: "uia"
  PROCESS_TRACK_MODE: "snapshot"

RECORD_SETTING:
  MODE: "failed"
  FPS: 5
  BUFFER_SECONDS: 8
  SEGMENT_SECONDS: 2
  MAX_WIDTH: 1280
  MONITOR_INDEX: 1
  FFMPEG_PATH: ""

RUN_INDICATOR_SETTING:
  ENABLED: true
  MAX_SCENARIO_CHARS: 28

SPARK_REPORT: true

OCR_SETTING:
  MODE: "accurate"
  TIMEOUT: 10
  INTERVAL: 0.5

PIC_SETTING:
  MODE: "accurate"
  THRESHOLD: 0.7
  TIMEOUT: 10
  INTERVAL: 0.3
```

| YAML 字段 | settings 属性 | 说明 |
| --- | --- | --- |
| `log.file` | `log_file` | `artifacts/logs/` 下的日志文件名 |
| `log.level` | `log_level` | `DEBUG`、`INFO` 等日志级别 |
| `APP_LAUNCH_MODE` | `app_launch_mode` | `auto` 启动应用，`attach` 连接已有应用 |
| `draw_outline_location` | `draw_outline` | 定位成功后是否高亮控件 |

| `APP_SETTING.PROCESS_TRACK_MODE` | `app_process_track_mode` | `snapshot`、`root` 或 `none` |
| `SPARK_REPORT` | `spark_report` | 是否生成 Spark HTML/JSON 报告 |

## 应用生命周期配置

`APP_LAUNCH_MODE=auto` 时，框架启动应用并在场景结束后清理拥有的进程；还会调用可选的
`Bdd.application.prepare_scenario()` 和 `cleanup_scenario()`。`attach` 不启停已有应用，
但仍调用这两个项目资源 Hook。

| `PROCESS_TRACK_MODE` | 清理范围 | 适用场景 |
| --- | --- | --- |
| `snapshot` | 启动前与首个 Step 前的 PID 差集，以及清理时仍关联的子孙进程 | 默认；适合启动器、BAT 或派生进程 |
| `root` | 启动命令返回的 PID 及仍挂载的子孙进程 | `APP_PATH` 直接启动主程序 |
| `none` | 不自动跟踪或清理进程 | 本地调试或外部平台管理 |

`snapshot` 在首个 Step 前等待 1 秒后冻结第二次快照；Step 内后来启动的进程不会混入。
清理时按叶到根终止并重试残留进程，但无法安全识别已脱离进程树、由已有服务后来启动
的产品进程。这类产品应使用 `APP_PATH=runtime` 的宿主 Stop。

`APP_PATH=runtime` 要求 `Bdd.application` 提供 `start_application()` 和
`stop_application()`，缺失即失败关闭。宿主 Stop 决定关闭对象；此时可把
`PROCESS_TRACK_MODE` 设为 `none`，避免无效快照。

## 录屏与运行提示

| `RECORD_SETTING` 字段 | settings 属性 | 说明 |
| --- | --- | --- |
| `MODE` | `record_mode` | `off`、`failed`、`all` |
| `FPS` | `record_fps` | ffmpeg 帧率，通常 `3~5` |
| `BUFFER_SECONDS` | `record_buffer_seconds` | `failed` 模式保留失败前多少秒 |
| `SEGMENT_SECONDS` | `record_segment_seconds` | 滚动缓存分片长度 |
| `MAX_WIDTH` | `record_max_width` | 视频最大宽度，`0` 为原分辨率 |
| `MONITOR_INDEX` | `record_monitor_index` | 录制屏幕索引 |
| `FFMPEG_PATH` | `record_ffmpeg_path` | 空值使用 `resources/ffmpeg/current/bin/ffmpeg.exe` |
| `FFMPEG_PRESET` | `record_ffmpeg_preset` | x264 preset |
| `FFMPEG_CRF` | `record_ffmpeg_crf` | 越大文件越小、质量越低 |
| `FFMPEG_DRAW_MOUSE` | `record_ffmpeg_draw_mouse` | 是否录入鼠标指针 |

`off` 不录屏；`failed` 使用滚动分片并只在失败时合并最近现场；`all` 完整直录并删除
通过场景的视频。OCR、PIC 和失败截图仍使用 mss。旧的 `RECORD: true/false` 不再读取。

`RUN_INDICATOR_SETTING.ENABLED=true` 时，普通 UI Scenario 在右上角显示当前场景与整次
Run 累计时长；窗口不抢焦点且鼠标穿透。`@api`、跳过场景和禁用配置不显示，提示异常
只记录 warning。

## settings_overrides

临时覆盖传给 `run_behave()` 或 `local_runner.main()`，即使运行失败也不会写回 YAML：

```python
settings_overrides = {
    "app_launch_mode": "attach",
    "log_level": "DEBUG",
    "draw_outline": True,
    "record_mode": "failed",
}
```

| 常用属性 | 示例 | 说明 |
| --- | --- | --- |
| `app_launch_mode` | `"auto"` | 启动模式 |
| `app_path` | `"notepad"` | 启动命令或路径 |
| `backend` | `"uia"` | pywinauto backend |
| `app_process_track_mode` | `"snapshot"` | 进程清理范围 |
| `log_level` | `"DEBUG"` | 本次日志级别 |
| `draw_outline` | `True` | 定位成功后画框 |
| `record_mode` | `"failed"` | 录屏模式 |
| `run_indicator_enabled` | `True` | 是否显示运行提示 |
| `ocr_timeout` / `ocr_interval` | `10` / `0.3` | OCR 等待与轮询 |
| `ocr_match_mode` | `"smart"` | OCR 匹配模式 |
| `pic_threshold` | `0.7` | 图片匹配阈值 |
| `pic_method` | `"mstpl"` | 图片匹配算法 |
| `pic_timeout` / `pic_interval` | `10` / `0.2` | 图片等待与轮询 |

这里必须写 `Settings` 属性名，不写 YAML 原始字段名。

## runner 参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `feature_path` | 必填 | Feature 文件或目录 |
| `settings_overrides` | `None` | 本次临时配置 |

| `verbose` | `True` | 是否输出启动诊断 |
| `formatter` | `None` | 如 `progress2`、`null`、`pretty` |

```python
from autowork_core.runtime.behave_runner import run_behave

run_behave(
    "Bdd/test_features/test_debug.feature",
    tags="not @skip",

```
