## 环境

推荐 Python 3.11。

安装基础依赖：

```powershell
python -m pip install -r requirements.txt
```

顶层`requirements.txt`统一声明框架及随仓库交付集成所需的Python包。产品设备、
供应商SDK和宿主专属二进制资产仍应在宿主项目文档中声明。

OCR 依赖当前验证组合：

```powershell
python -m pip install --pre paddlepaddle==3.0.0.dev20250426 -i https://www.paddlepaddle.org.cn/packages/nightly/cpu/
python -m pip install paddleocr==3.6.0
python -m pip install opencv-contrib-python==4.6.0.66 PyYAML==6.0.2
python -m pip check
```

注意：`paddleocr==3.6.0` 会拉取 `paddlex==3.6.1`。PaddleOCR 可能升级 OpenCV，但本项目同时依赖 `airtest==1.4.3`，它要求 `opencv-contrib-python<=4.6.0.66`，所以安装 PaddleOCR 后需要把 OpenCV 恢复到 `4.6.0.66`。

## 同步框架到项目仓库

框架仓库和产品项目使用独立Git仓库。项目维护者拉取框架仓库后，完整替换项目仓库中的
以下框架资产：

```text
autowork_core/
ai/
docs/
.github/
resources/
requirements.txt
behave.ini
README.md
.gitattributes
.gitignore
```

完整替换前，项目仓库不应修改这些框架资产。始终保留`Bdd/`、`config/`和`artifacts/`；
其中`Bdd/ai/`保存项目身份和项目知识，也不得被框架替换。`framework_validation/`只属于
框架开发仓库，不复制到宿主项目。同步后检查Git diff并运行轻量检查：

```powershell
python -B -m autowork_core.utils.debug_tools.framework_smoke --project-root .
```

该命令只检查文件、配置、关键导入和Runner，不启动应用、OCR、ffmpeg或Recorder全量
测试。只有本次同时修改了`Bdd/`或`config/`，才运行对应项目测试。该流程不使用跨仓库
`git merge`，也不依赖额外同步脚本。

## 运行入口

建议从项目根目录使用模块方式运行，避免脚本路径导致 `config`、`autowork_core` 等顶层包导入失败。

正式用例：

```powershell
python -m Bdd.runner
```

正式入口默认读取 `Bdd/features`。当前仓库示例用例放在 `Bdd/test_features`；如果还没有创建正式用例目录，请先使用本地调试入口运行示例 feature。

本地调试用例：

```powershell
python -m Bdd.local_runner
```

指定要调试的 feature：

```powershell
python -m Bdd.local_runner Bdd/test_features/test_debug.feature
```

### VS Code 运行和调试

框架迁移到宿主项目下后，推荐建立多根工作区，并把 `bdd_autowork` 本身作为一个独立工作区文件夹加入。不要只把它当作宿主目录中的普通嵌套文件夹。

仓库内 `.vscode` 配置会提供项目根和工作目录，因此可以在任意层级的 `.py` 文件中
使用：

- `Run > Python File in Terminal`
- `Python Debugger: Debug Python File`

迁移或第一次加入工作区后，请执行一次 `Developer: Reload Window`，关闭旧 Python 终端并重新创建终端，再为 `bdd_autowork` 文件夹选择正确解释器。

只定义类或函数的文件运行后没有输出属于正常现象；要调试其中逻辑，需要测试或入口
实际调用它。在 VS Code 外直接执行深层文件时，应从项目根使用模块入口，或自行配置
`PYTHONPATH`。

直接运行 behave 也可以：

```powershell
python -m behave Bdd/features --no-capture --no-capture-stderr --no-logcapture --verbose
python -m behave Bdd/test_features --no-capture --no-capture-stderr --no-logcapture --format progress2 --verbose
```

## 本地调试入口

命令行传入的 Feature 路径优先于本地默认值：

```powershell
python -m Bdd.local_runner Bdd/test_features/test_debug.feature
```

需要固定应用路径、backend、日志或录屏模式时，使用本地 runner 的
`settings_overrides`；字段和示例见
[4.定位器与配置：settings_overrides](4.定位器与配置.md#settings_overrides)。

### 单步调试

本地 runner 支持通过一个 Scenario 标签选择目标 Step。普通 Scenario 使用：

```gherkin
@single:background:3
Scenario: Verify scan
```

Scenario Outline 还需要选择第几个 `Examples` 及其中第几条数据行：

```gherkin
@single:previous:2:example=1.2
Scenario Outline: Verify scan with <phase>
```

标签格式为 `@single:<mode>:<step-index>[:example=<examples-index>.<row-index>]`。
序号从 `1` 开始。模式含义：

| mode | 执行内容 |
| --- | --- |
| `previous` | Background、目标前的 Scenario Steps、目标 Step |
| `background` | Background、目标 Step |
| `none` | 仅目标 Step，界面和数据状态由使用者负责 |

整个本地运行只能存在一个 `@single:` 标签；Outline 必须提供 `example=组.行`。
正式 `Bdd.runner` 不处理这个调试标签。

常用 formatter：

| formatter | 效果 |
| --- | --- |
| `"progress2"` | 当前推荐，输出简洁进度，控制台仍保留框架日志 |
| `"null"` | 不输出 Feature/Scenario/Step 文本，控制台最安静 |
| `"pretty"` 或 `None` | 输出完整 Feature/Scenario/Step 文本，适合核对步骤顺序 |
| `"progress"` | 输出简短进度符号 |

## 标签筛选

```powershell
python -m behave Bdd/features --tags=@smoke
python -m behave Bdd/features --tags="@smoke and @login"
python -m behave Bdd/features --tags="@smoke or @regression"
python -m behave Bdd/features --tags="not @skip"
```

## 输出产物

| 目录 | 内容 |
| --- | --- |
| `artifacts/logs/` | loguru 日志 |
| `artifacts/screenshots/` | 失败截图、OCR/图片调试图 |
| `artifacts/recordings/` | 失败场景录屏和 ffmpeg 临时分片 |
| `artifacts/recording_sessions/` | Feature Step Recorder 的逐 Step 录制会话 |
| `artifacts/reports/` | 报告输出目录 |
| `artifacts/run-results/` | 与生成事务绑定的内容寻址运行结果 |

本地 runner 默认清理上一轮截图、普通录屏和报告。Recorder 会话位于
`artifacts/recording_sessions/`，不会随普通用例运行自动清空。

`artifacts/`只保存当前宿主项目的运行产物。框架测试通常写入操作系统临时目录；维护者
评测及历史验收工作区写入Git忽略的`framework_validation/output/`，不会混入这里。

Spark 报告默认输出：

| 文件 | 说明 |
| --- | --- |
| `artifacts/reports/autowork-report.html` | 可直接打开的本地 HTML 报告 |
| `artifacts/reports/autowork-report.json` | 报告原始数据，便于排查步骤顺序、截图附件和状态聚合 |
